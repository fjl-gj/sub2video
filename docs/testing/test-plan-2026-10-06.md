# Sub2Video 完整测试流程与 UI 自动化计划

日期：2026-10-06。范围：现有三模式单镜头生成、作品/素材/钱包/工单、最小导演台、管理端配置与恢复。当前分支 `codex/commercial-studio-redesign`。这是可重复执行的计划，实际结果见 [本轮执行记录](test-process-acceptance-2026-10-06.md)。

不增加支付、新模型、新供应商或影片剪辑工程。本轮继续完善已有功能和验证流程；不进行部署、提交或付费生成。

## 1. 要证明的用户路径

了解产品 → 登录 → 选择模式和模型 → 准备素材 → 合法估价 → 明确提交 → 钱包预扣/任务创建 → Worker 执行 → 成功交付或有依据的失败退款 → 下载 → 保存到作品 → 再次创作。

导演台增加一条准备路径：作品 → 镜头清单 → 编辑与保存 → 带镜头上下文进入创作 → 用户显式应用 → 估价和提交 → 候选归属原镜头 → 选择成片。不能把“保存剧本/镜头”表述为已经生成视频。

正式创作合同是 `POST /client/tasks/estimate` 与 `POST /client/tasks`。估价无 quoteId、锁价凭证或过期校验；提交重新计算。`estimate` 返回可用仅证明这一时刻的预检，不保证后续上游执行成功。

## 2. 测试分层与不能越过的结论

| 层 | 输入与运行环境 | 主要断言 | 不能证明 |
| --- | --- | --- | --- |
| S：静态与构建 | ESLint、Vue 类型、Go 编译、Vite production build | 合同类型、语法、部分样式所有权和产物可构建 | 可操作、真实计费、布局美观 |
| U：Go 单元/本地 HTTP 故障 | 合成凭据、httptest、本地 fixture | 参数验证、上游错误分类、签名调用、DTO 脱敏 | 真实供应商接受或真实存储可用 |
| B：浏览器 Mock 交互 | Playwright、当前 Vue、确定性响应 | 点击、焦点、请求参数、等待/失败/空状态、导航和防双击 | 后端事务、持久化、扣费和交付 |
| V：视觉与几何 | 固定字体/图片/数据、六档 CSS 宽度 | 对齐、溢出、遮挡、表格局部滚动、截图基线 | 整站审美自动合格、真机键盘或全站无障碍认证 |
| D：真实数据库 | 专用 PostgreSQL/Redis、随机 schema | 迁移、并发幂等、金额守恒、回滚、归属、快照、租约 | 真实供应商、真实视频解码；Redis 探针不证明验证码生命周期 |
| R：真实 API 只读 | 明确版本的 UAT 或本地前端连接 UAT | 登录、目录、公开错误、无扣费估价、余额前后相同 | 新版本后端已经部署；上传/提交/保存写入 |
| W：受控写入 | 专用隔离账号、对象前缀、独立作品 | 上传、持久保存、刷新定位、权限拒绝 | 未经授权的付费执行 |
| P：真实交付 | 经确认的参数、账号、费用与硬预算 | 实际生成、对象存储、可播放下载、对账 | 全量用户长期稳定性与商业化完成 |

Go `httptest` 启动了 HTTP 服务仍是故障注入。Mock 返回 `completed`、假下载 URL、Toast 或 HTTP 200 均不能作为 P 层证据。

与用例库证据代码的对应关系：本计划B对应M（Mock），R对应L的只读部分，W对应L的受控写入并可能需要O（真实对象存储）；P交付阶段同时需要L/O/P证据。用例库H是人工/真机，S是本计划额外列出的静态检查层。U/V/D含义一致。

## 3. 环境和数据隔离

### 本地 UI

沿用 Vue 3 / TypeScript / Vite / Pinia / Reka UI 与 Playwright，不额外引入测试框架。`frontend/tests/e2e` 是 Mock 浏览器合同；`frontend/tests/integration` 是显式启用的真实 API 场景。当前项目没有建立 Vitest、axe 或跨浏览器 CI，不把它们写成已接通。

统一固定 locale、字体、图片、时间相关 fixture、减少动画。通过 role/label/可访问名称定位；几何断言可以读取由设计系统拥有的布局类，不能依赖临时 Tailwind 排列。缺失 Mock 请求必须拒绝并记录，不转发真实后端。不使用任意 sleep 等待加载，用响应、状态和可观察 DOM 等待。

桌面项目为 Chromium 1440×900；手机项目为桌面 Chromium 的390×844触摸视口。它不是 iOS Safari 或真实 Android 设备。六宽度矩阵单独覆盖320、390、768、1024、1440、1920；具体高度与例外见 UI 标准。

### 真实数据库

运行前读集成测试真实实现，确认库名含 `test`、随机 schema、不回退 public、Redis只用专属 key。仅库名包含 test 并不足以证明可销毁，还必须核对库属于本轮测试且不被 UAT 服务引用。缺少环境不能通过临时把变量指向 UAT 业务库解决。

本轮实际创建专用容器和内部网络，数据库数据放 tmpfs，无主机对外端口，通过只绑定127.0.0.1的 SSH 转发连接。UAT 服务、原 PostgreSQL、原 Redis、MinIO、业务数据不变。执行完成检查残留 schema/key，再仅删除本轮标记的容器和网络。

环境变量作用：

| 变量 | 用途与前置 |
| --- | --- |
| `SUB2VIDEO_RUN_INTEGRATION=1` | 启用 opt-in 集成测试，不代表基础设施可达 |
| `SUB2VIDEO_TEST_DATABASE_URL` | 专用测试库；测试动态创建 schema，连接信息只在进程内存中提供 |
| `SUB2VIDEO_TEST_REDIS_URL` | 专用 Redis 或经过确认的命名空间；当前 store helper 做 SET/GET/DEL 探针 |
| `SUB2VIDEO_TEST_MINIO_ENDPOINT`、`SUB2VIDEO_TEST_MINIO_ACCESS_KEY`、`SUB2VIDEO_TEST_MINIO_SECRET_KEY` | 独立对象存储环境；不是自动读取 UAT 生产配置 |
| `SUB2VIDEO_TEST_MINIO_BUCKET`、`SUB2VIDEO_TEST_MINIO_SSL`、`SUB2VIDEO_TEST_MEDIA_FILE` | 测试桶名称含 test，媒体文件真实存在；按测试实际要求配置 |

数据库和 Redis 设置正确也不自动运行 MinIO 测试。无存储变量时必须报告该测试 SKIP。

### UAT 与受控写入

只读入口要求明确 `SUB2VIDEO_UAT_PROFILE`：`ready` 要求页面实际选择文生模式、承运商、模型及5秒/768P/16:9/无自动音频，等待对应请求成功、页面金额一致和提交按钮可用，但不点击提交；`unconfigured` 期望公开可理解的不可用状态。第二种通过仅代表故障表达正确，不代表可以邀请用户生成。当前ready入口只覆盖文生，不能代替三模式正向验收。

认证请求与无副作用估价是允许的 POST；其他业务写入由浏览器 route guard 拒绝，并限制目标为同源API。专用只读套件使用页面内 `fetch`，Token不传回测试进程，只允许列出的读取路径与estimate，因此同样受路由守卫约束；同时禁止Service Worker。不得换成绕过页面守卫的 `page.request`，其失败调用日志还可能记录Authorization头。

使用已有专用账号或授权的登录读取。受控写入另选命名如 `qa-<run-id>` 的账号、作品及素材前缀；记录确切创建对象ID，只清理这些对象。禁止跨用户修改、共享余额调整、供给/价格变更以及全库清理。

真实 paid 任务须先列：模式/模型/素材、时长/分辨率/比例/音频、账号、每笔估价、总预算、每模式最大任务数、失败停止条件。没有这些批准不得自动提交；网络错误不得无限重试。

## 4. 用例设计方式

用例库见 [test-cases-2026-10-06.md](test-cases-2026-10-06.md)。用例 ID 用于跨版本追踪，不随文案变动重编号。每条包含优先级、角色与前置、步骤、可观察预期、现有自动化映射及缺口。

每个功能至少覆盖：正常、边界、空数据、加载中、后端错误、网络中断、权限、重复操作、刷新恢复。金额、幂等和归属用真实 DB 断言，不能只看按钮。用户主观满意度另由创作者访谈记录，不通过测试脚本捏造评分。

参数组合先按等价类和边界测试，再选高风险交叉：

| 参数 | 最少覆盖 |
| --- | --- |
| 模式 | 文生、首尾帧、多图；切换后素材与参数兼容性 |
| 模型/承运商 | 明确指定、默认推荐、禁用、不兼容；不得静默跨模型 |
| 时长/数量 | 最小、最大、越界、缺失；图片0/1/上限/上限+1 |
| 音频 | 支持且开/关、不支持；本轮不扩展参考音频 |
| 费用 | 未估价、等待、估价失败、恰好足额、差一分、重复提交 |
| 上游提交 | 明确未受理、明确已受理、无法确认；408/4xx不可一概退款 |
| Worker | 首次claim、租约竞争、旧Worker回写、deadline、存储等待、核对恢复 |
| 资产/导演台 | 本人/他人、删除、revision冲突、并发保存、候选未就绪 |

这张表是目标覆盖，不是全部已通过：当前TC-020/021/046及其映射只覆盖部分合法/越界和余额不足场景；“恰好足额/差一分”、每种执行能力的时长最小/最大和图片上限/上限+1仍需补精确参数化用例及执行记录。

## 5. UI 自动化具体范围

三组检查互补：

1. **行为合同**：真实DOM点击/输入/Tab/Enter/Escape，验证请求参数、用户选择保留、加载错误区分、提交禁用原因、焦点返回、导航回跳。
2. **几何合同**：可触达主操作≥44px；trial click加五点命中；底栏避让；main和document无横向溢出；侧栏剩余空间内对齐；表格只在本容器横向滚动；弹窗留在屏幕内。
3. **截图回归与审图**：固定输入下整页/组件截图；桌面和手机人工查看原图、新图和差异。只有有意的设计修改才能更新相应基线，不提高容差隐藏问题。

本轮新增创作可用性合同：没有供给、模型组合不支持、网络失败可重试、服务错误、存储错误可重试，并验证草稿模型和描述保留、内部诊断不泄露、不发起生成。新增 UI 标准合同覆盖六宽度、两个表面的焦点循环与关闭回焦、移动导航关闭。

完整尺寸、颜色、所有权、WCAG补充检查、长内容、200%浏览器缩放和真机缺口见 [ui-layout-acceptance.md](ui-layout-acceptance.md)。JS `deviceScaleFactor=2` 不能冒充200%浏览器缩放；无横向滚动也不能靠隐藏溢出而丢失内容。

## 6. 每轮执行顺序

| 阶段 | 操作 | 输出与退出条件 |
| --- | --- | --- |
| 0 身份与权限 | AGENTS、设计系统、分支/HEAD/status、源码摘要；确认目标版本和测试账号 | 明确已有修改及可写范围；无法识别环境则停止写入 |
| 1 静态与局部回归 | lint/typecheck、相关Go/Playwright用例 | 先修可复现缺陷；失败截图/trace仅留隔离Mock数据 |
| 2 数据库 | 专用PG/Redis，`go test -count=1 -json ./...` | 逐项读取fail/skip；验证迁移集合、财务原子性、租约和归属 |
| 3 全量UI与构建 | `pnpm test:visual`、`pnpm build` | 所有必需用例通过；有意截图变化已审图；无任意容差变更 |
| 4 真实只读 | 严格只读入口，记录远端运行SHA与前端来源 | 登录/目录/公开状态/余额无变化；不掩盖unconfigured |
| 5 受控写入 | 专用账号素材上传、保存、刷新、返回创作 | 存在真实持久记录，无自动生成；清理只针对本轮对象 |
| 6 实际交付 | 授权后有限次真实任务 | 明确上游受理、账务、成片、可播放下载和保存证据 |
| 7 交付与清理 | diff检查、结果记录、缺陷与残留列表 | 清理本轮资源；提交/部署状态单列，不自动执行 |

阶段5/6需要条件时，继续完成不依赖它们的0–4与7；报告BLOCKED与最小缺失项，不能把整轮写成全部通过。

日常修改不必重复跑重叠命令。改页面先相关contract；改shared组件/布局必须完整视觉回归；改钱/任务/Worker须真实数据库；候选发布覆盖全部适用层。

## 7. 执行命令与结果检查

在 `frontend/`：

```text
pnpm lint:check
pnpm typecheck
pnpm test:ui:interaction --reporter=dot --output=../.tmp_<task>_<id>/interaction
pnpm test:ui:layout --reporter=dot --output=../.tmp_<task>_<id>/layout
pnpm test:visual --reporter=dot --output=../.tmp_<task>_<id>/full-ui
pnpm build
```

在 `backend/`，先通过进程环境安全注入隔离测试配置：

```text
go test -count=1 -json ./...
```

捕获JSON事件到本轮临时目录，汇总顶层测试和子测试，区分没有test文件的包与真正 `t.Skip`。检查 `Action=fail`、每个 `Action=skip` 的原因以及集成测试名称；不能只数进程退出0。基于当前代码的所需集合动态读取迁移，不硬编码21个文件。

真实只读命令见测试入口。原 `pnpm test:integration` 仍保留 opt-in行为，缺少变量时可能跳过；不把它单独作为发布门禁。真实环境配置禁用自动retry、trace、录像和失败截屏，但旧 `live-*` 套件尚未完成同等的失败日志加固，不能据此声称凭据产物安全。新严格只读入口额外避免将密码作为fill调用参数，失败时清空表单，页面内读取Token，以固定错误码替代网络原始异常，并禁用Playwright 1.62的隐式页面快照。只保留脱敏状态码、统计、公共错误码和必要ID。升级Playwright时必须用合成邮箱/密码/Token制造登录和认证网络失败，重新扫描日志、JSON报告及error-context，不能依赖未验证的内部开关。

## 8. 缺陷处理与证据记录

失败先归因：产品缺陷、测试fixture错误、测试断言错误、环境不可用、未实现。附最小复现、实际/期望、版本、数据前置及影响。禁止先改快照再解释，禁止为了未实现API适配器而伪造成功。

| 状态 | 定义 |
| --- | --- |
| PASS | 本轮指定环境确实执行，所有观察点满足 |
| FAIL | 执行后发现不满足，保留问题和复测结果 |
| SKIP | 测试框架主动跳过；解释环境或重复矩阵原因 |
| BLOCKED | 用例必要条件缺失，尚不能执行 |
| NOT RUN | 本轮未运行，不能引用旧结果替代 |

证据记录模板：`run-id / 源码HEAD+脏工作区摘要 / 部署SHA / 环境与账号别名 / TC-ID与实际test名 / 层 / 命令 / 通过失败跳过数 / 实际观察 / 产物摘要 / 清理 / 剩余问题`。脱敏ID应在同一报告中稳定，以便扣费订单与任务对账；不要记录完整JWT、连接串或供应商响应原文。

Mock可保留失败trace，但上传附件也须符合授权范围。真实凭据只在内存中使用；不启用调试网络dump。工作区中不提交报告HTML、视频、归档、日志或临时认证状态。

## 9. 发布和封闭试用门槛

**可合并/候选源码门槛**：静态、构建、所需单元和交互通过；共享视觉变更已审图；P0为0；涉及财务/任务的D层通过且不存在被skip掩盖的关键场景。

**可部署门槛**：同版本产物摘要、迁移需求、进行中任务和回滚兼容性已确认；本轮不因测试通过自动部署。

**5～10位创作者生成试用门槛**：三模式可用组合估价+授权交付、可播放下载+持久保存有当前版本真实证据；无重复扣费/越权/数据丢失；未受理失败退款准确，受理不确定可核对；主要手机路径可操作。对象存储/供应商未配置是生成试用P1，不能由UI绿灯抵消。

P0：错误扣费、越权、数据丢失；P1：主路径中断、状态误导、不能恢复、手机主要操作受阻；P2：不阻断的文案、层次和一致性。未接支付保持“在线充值暂未开放”，不以模拟充值通过作为收入闭环。
