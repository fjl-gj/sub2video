# Sub2Video 产品方案总览

## 产品定位

Sub2Video 是面向创作者的视频生成平台，首期围绕 MiniMax H3 建立“找灵感 → 配置工作流 → 生成任务 → 查看作品 → 保存资产 → 钱包扣费”的闭环。它不是 API 聚合、账号分发或渠道代理平台。

客户端只呈现创作能力和账户服务；供应商密钥、渠道余额、并发限制、调度策略和对象存储细节只存在于管理端与后端。

## 客户端菜单

```text
首页概览

创作空间
  创作
  创意园
  作品
  资产

钱包
帮助与工单
```

个人资料从右上角头像进入，不占用高频主导航，包含个人资料、账号安全、登录设备和退出登录。

### 客户端职责

| 菜单 | 职责 |
| --- | --- |
| 首页概览 | 查看余额、进行中任务、最近作品和灵感入口 |
| 创作 | 选择工作流、上传素材、填写提示词、选择参数、确认价格并提交任务 |
| 创意园 | 浏览官方场景和预设提示词，一键带入创作页 |
| 作品 | 跟踪排队、生成中、完成和失败任务；下载、重试、保存到资产 |
| 资产 | 管理用户主动保存的图片、视频、音频和成片 |
| 钱包 | 充值、兑换、订单和余额流水；不做订阅和 API 套餐 |
| 帮助与工单 | 处理充值、生成异常、退款和售前咨询 |

工作流采用配置驱动。首期可启用 H3 图生视频，768P、15 秒只是初始可选配置，不写死在页面中；文生视频和多图生视频先保留工作流形态，待供应商能力确认后上架。

### 管理端职责

| 分组 | 职责 |
| --- | --- |
| 首页概览 | 查看任务量、收入、成功率、异常和供应状态，不在此处做配置 |
| 工作流 | 定义输入、参数、输出、上架状态，并映射模型和价格规则 |
| 模型与供应商 | 管理供应商凭据、健康状态、并发能力和可用模型 |
| 定价规则 | 管理成本、售价、活动价和版本；任务创建时固化价格快照 |
| 充值商品 | 配置用户购买的余额档位和支付通道 |
| 订单管理 | 查询充值、到账、关闭和退款订单 |
| 任务中心 | 查询、重试、退款和处理生成异常 |
| 用户管理 | 查看用户、余额、作品、订单和账户状态 |
| 工单中心 | 处理用户服务请求并关联任务和金额 |
| 公告 | 发布价格、服务状态和规则变更 |
| 运维监控 | 查看供应商健康、队列、失败率、延迟和资源状态 |
| 操作日志 | 审计管理员对任务、定价、工作流和用户的操作 |
| 系统设置 | 配置存储留存、通知和平台级开关 |

场景模板和内容审核 / 风险任务在没有真实运营策略前隐藏，不展示空页面。

## 核心数据边界

```text
工作流 → 模型与供应商 → 生成任务 → 作品
定价规则 → 任务价格快照 → 钱包流水
创意园预设 → 创作
资产 → 创作
作品主动保存 → 资产
充值订单 → 钱包余额
```

素材按生命周期管理：任务输入默认短期保留（例如 7 天），生成结果在作品中保留（例如 30 天），只有用户主动保存的内容进入长期资产额度。客户端显示容量和有效期，不显示 OSS、Bucket 或供应商路径。

## 技术方案

前端采用 Vue 3、TypeScript、Vite、Vue Router、Pinia、Tailwind CSS 3.4、Reka UI、tailwind-variants、clsx、tailwind-merge 和 Lucide Vue。客户端与管理端共享基础组件和设计令牌，但使用独立 Layout、路由命名空间和权限边界。

后端接入阶段可复用 Sub2API 的用户、认证、角色、钱包、订单、日志和 Go 工程基础；API Key、渠道和代理模型不直接暴露给客户端，改造成管理端的 Provider 供给层。MySQL 承载事务数据，Redis 负责队列和状态，OSS 负责素材和结果。当前阶段全部使用确定性的本地 Mock，不接 Go、Redis、MySQL、OSS、支付或真实供应商。

## UI 修改边界

视觉配方以 [`docs/原型设计/sub2video-client.html`](./原型设计/sub2video-client.html) 和 [`docs/原型设计/sub2video-admin.html`](./原型设计/sub2video-admin.html) 为准。导航名、路由和作品 / 资产对象模型以本文件为准，不要把 HTML 侧栏结构搬进 Vue。

```text
全局颜色、字体、圆角、阴影 → shared/styles/tokens.css / tailwind.config.ts
通用组件外观和变体       → shared/ui
产品特有交互和特殊视觉     → features
页面布局、顺序和响应式组合   → widgets / pages
```

页面允许使用 `grid`、`flex`、`gap`、`max-w` 等布局工具，但不能硬编码颜色、边框、圆角、阴影或按钮配方。所有 AI 工具先阅读 `docs/ui/design-system.md`，并通过 `AGENTS.md`、Cursor Rules、ESLint、TypeScript、构建和视觉回归共同约束。

## 实施顺序

1. 建立 `design-system.md`
2. 建立 `AGENTS.md` 和 Cursor Rules
3. 建立 Tailwind 令牌与 `cn.ts`
4. 建立 S2V 基础组件
5. 建立客户端和管理端 Layout
6. 迁移客户端首页和创作页
7. 迁移作品、资产、钱包、工单
8. 迁移管理端首页、工作流、任务中心
9. 迁移计费、用户、供应商和运维
10. 加入登录、注册和邮箱验证
11. 加入桌面端和手机端视觉回归
12. 以后再接入 Go、Redis、MySQL、OSS、支付和真实 Provider
