# 创作模式、模型选择与供应商路由设计

## 1. 文档目的

本文定义 Sub2Video 当前视频生成合同、后台执行配置、预估/提交计费和任务执行边界。2026-10-04 按现有代码收敛；历史 workflow/quote/offering 迁移结构见第 7 节，不作为新业务入口。

目标是同时满足以下要求：

1. 客户端永久只提供三种创作模式，不把供应商、渠道、工作流 ID 或成本暴露给创作者。
2. 创作者可以选择承运商和模型；未选择时由平台按明确的推荐策略选择模型。
3. 同一个模型可以由官方和多个第三方供应商供给，平台能在不改变用户模型选择的前提下选择合适的供应商。
4. 供应商成本与平台对客售价独立维护；创建任务时同时固化两类价格和执行路由。
5. 时长按秒作为计费数量。只有供应商存在固定套餐或时长阶梯折扣时，才需要额外的时长价格规则。

本文不设计面向客户的 API Key、供应商账户、渠道余额或代理管理功能。

## 2. 已确认的产品决定

### 2.1 客户端模式固定为三种

| 模式代码 | 客户端名称 | 必填输入 | 不变约束 |
| --- | --- | --- | --- |
| `text_to_video` | 文生视频 | 提示词 | 不上传图片 |
| `first_last_frame_to_video` | 首尾帧生成视频 | 提示词、首帧图片、尾帧图片 | 首尾帧均必填 |
| `multi_image_to_video` | 多图生成视频 | 提示词、至少一张参考图 | 图片上限由模型供给定义 |

这三个模式是系统产品合同，不允许管理员新增第四种客户端模式，也不允许将上游工作流名称直接作为模式。管理端“工作流”只负责上架、下架、排序和展示文案；模式模型策略维护支持关系、推荐顺序和默认参数。平台售价单独维护，不绑定模型。

### 2.2 模型选择对用户可见，供应商对用户不可见

客户端的选择顺序为：

```text
创作模式
  -> 承运商（可选筛选）
  -> 模型（可选；默认智能推荐）
  -> 视频时长 / 分辨率 / 画幅 / 自动生成音频
  -> 预估费用（不持久化、不锁价）
  -> 提交
```

承运商是模型原厂，例如 MiniMax、火山引擎。模型是原厂的具体型号，例如 H3、Seedance 2.0、Seedance 2.5。供应商是实际采购和调用渠道，例如官方 MiniMax、官方火山引擎、AutoDL；它只存在于管理端和后端。

模型选择不是第四个创作模式。一个模型可以同时支持文生视频、首尾帧和多图生成，用户在模式内选择模型只是表达质量、风格或能力偏好。

### 2.3 自动生成音频的定义

现有客户端音频设置有三项：不使用音频、模型自动生成音频、上传参考音频。后两项使用 `generateAudio = true` 参与能力筛选和平台音频售价；上传参考音频时，额外提交 `sourceMeta.audio`。参考音频是可选增强素材，未上传时音频能力仍可生成。这里记录已有实现，本轮不扩展参考音频流程或新增音频模型。

只有供应商执行配置明确声明 `supports_generated_audio = true` 且存在对应上游参数映射时，客户端才可显示音频设置。参考音频文件先进入受控上传与任务快照，由 Worker 上传对象存储后按执行映射传递给上游；客户端不返回供应商、工作流编码或上游地址。经鉴权的签名预览/下载地址是合法交付字段，不应与上游地址混为一谈。

## 3. 当前领域模型

```text
创作模式 --- 模式模型策略 --- 模型 --- 承运商
创作模式 --- 平台售价（模式 × 分辨率 × 音频 × 版本）
供应商 --- 供应商模型绑定 --- 执行配置 --- 供应商成本
                              |
                         API / workflow

预估 --- 读取当前能力与价格，只返回计算结果
提交 --- 幂等检查、重新路由、原子扣费/订单/任务、不可变快照
```

### 3.1 创作模式 `creation_modes`

该表只保存三个系统种子数据，`code` 受服务端白名单约束。管理员页面只能编辑展示名称、说明、排序和上架状态，不能创建或删除模式。

| 字段 | 说明 |
| --- | --- |
| `id` / `public_id` | 内部和对外标识 |
| `code` | 三个固定模式代码之一 |
| `name` / `description` | 客户端展示文案 |
| `status` | `published`、`disabled` |
| `sort_order` | 客户端排序 |
| `input_contract` | 系统生成的只读输入合同快照，用于审计和接口返回 |

`input_contract` 不接受管理员自由编辑，以避免页面控件与后端校验分叉。输入校验以模式代码的服务端实现为准。

### 3.2 承运商 `carriers`

承运商代表模型原厂，可新增、查询、编辑和停用/启用。首批种子为 MiniMax 和火山引擎。有历史任务引用时只允许停用，不物理删除。

### 3.3 模型 `models`

模型归属一个承运商，可新增、查询、编辑和停用/启用。模型只描述原厂型号，不携带某个供应商工作流 ID，也不再使用单值 `client_workflow_id`，因为一个模型可支持多个创作模式和多个供应商供给。

| 字段 | 说明 |
| --- | --- |
| `carrier_id` | 模型原厂 |
| `code` | 稳定机器编码，如 `h3`、`seedance_2_0` |
| `name` / `description` | 管理端和客户端展示 |
| `enabled` | 是否允许新建供给和展示给用户 |
| `sort_order` | 同承运商下的排序 |

模型不能因为某个供应商下线而直接消失。客户端仅在该模型存在至少一个可报价的供给时显示为可用。

### 3.4 模型配置 `mode_model_policies`

`mode_model_policies` 声明模型支持哪些固定创作模式，并控制未选择模型时的推荐顺序与默认参数。它不是售价表，也不代表供应商的实际执行能力。

| 字段 | 说明 |
| --- | --- |
| `mode_id` / `model_id` | 唯一组合 |
| `enabled` | 是否允许客户端主动选择 |
| `recommendation_rank` | 智能推荐时从小到大选择 |
| `display_badge` | 可选客户端角标，如“推荐”“高质量” |
| `default_resolution` / `default_duration` | 仅作默认值，必须在可用供给范围内 |

当前“智能推荐”先按 `recommendation_rank` 选择目录中有可用供给的模型，再校验该模型的实际请求参数；参数不满足时返回组合不可用，不自动尝试另一模型。选定模型后，才在该模型的供应商执行配置中按成本选择。若未来要让智能推荐遍历所有模型参数，必须单独定义合同与测试，不能悄悄改变明确选择模型时的行为。

### 3.5 供应商 `suppliers`

供应商代表采购渠道，维护连接信息、凭据、健康状态和运营状态。凭据必须加密保存，任何客户端 API、前端 bundle、任务列表、报价响应都不能返回供应商名称、编码、成本、连接地址或上游工作流 ID。

官方渠道与第三方渠道使用相同模型：官方 MiniMax、官方火山引擎均是供应商记录，并不拥有特殊的客户端展示权限。

### 3.6 供应商模型绑定与执行配置

`supplier_model_bindings` 记录供应商是否支持某模型，包含 `supplier_id`、`model_id`、`enabled`、`status`。正式路由单元是 `supplier_executions`，一条配置表示该绑定可用哪种执行方式完成某模式。

| 字段 | 说明 |
| --- | --- |
| `binding_id` / `mode_id` | 供应商模型绑定及客户端模式 |
| `execution_type` | 仅后端使用的 `api` 或 `workflow` |
| `api_model_code` / `api_version` / `workflow_code` | API 或工作流的上游编码；API 必须有模型编码，workflow 必须有工作流编码 |
| `adapter_code` | 参数与结果转换器，例如 `autodl_h3_v1` |
| `enabled` / `health_status` / `quota_status` | 启用、健康和额度共同决定是否参与候选 |
| `priority` | 同成本供给的运营优先级 |
| `min_duration_sec` / `max_duration_sec` | 可接受的时长范围 |
| `resolutions` | 支持的标准分辨率，如 `480P`、`768P`、`1080P` |
| `aspect_ratios` | 支持的画幅比例 |
| `min_images` / `max_images` | 当前执行配置支持的图片范围；首尾帧还受模式本身的必填约束 |
| `supports_generated_audio` | 是否可无参考音频地生成音频 |
| `parameter_mapping` / `result_mapping` | 供应商私有参数与结果映射，仅供已实现的 Adapter 使用 |
| `legacy_offering_id` | 对历史 offering 的兼容关联；不是客户端参数 |

同一供应商、模型和模式可以有多个执行配置。API 和 workflow 在满足能力后共同参与最低成本选择，但数据库允许该类型不代表当前 Adapter 已实现；未验证的 API 协议必须被过滤。`supplier_offerings` 暂为历史桥接，管理写入必须和 execution 同事务，不能部分成功。

### 3.7 供应商成本规则 `supplier_cost_rules`

正式成本规则绑定执行配置；通过绑定关系确定供应商与模型，不属于平台售价。标准价格粒度为每秒。

| 字段 | 说明 |
| --- | --- |
| `execution_id` | 对应供应商执行配置；`offering_id` 只保留历史关联，可为空 |
| `resolution` | 输出分辨率 |
| `generate_audio` | 自动音频开关 |
| `price_per_sec_peak` / `price_per_sec_offpeak` | 高峰/低峰采购单价 |
| `version` | 成本规则版本，随任务和订单保存快照 |
| `effective_from` / `effective_to` | 合同价格生效区间 |
| `currency` | 首期固定 `CNY` |
| `status` | `active`、`draft`、`expired` |

对于“按实际输出时长收费”的供应商，供给需要声明 `billing_basis = actual_output_duration`。首期三种视频模式只上架 `requested_duration` 计费的供给；实际时长计费在支持前必须增加预授权、最终结算和差额退款流程，不能复用现有预扣逻辑。

### 3.8 平台售价规则 `retail_price_rules`

用户可见的售价独立于供应商成本，主键为：

```text
创作模式 × 分辨率 × 是否生成音频 × 价格版本
```

| 字段 | 说明 |
| --- | --- |
| `mode_id` | 客户端创作模式 |
| `resolution` / `generate_audio` | 输出参数；参考音频也属于音频生成请求 |
| `price_per_sec` | 对客每秒单价；API 使用 `pricePerSecond` |
| `version` | 提交时任务和订单快照使用的版本 |
| `status` | `active`、`draft`、`disabled` |
| `effective_from` / `effective_to` | 调价生效区间 |

时长不在规则唯一键中。标准总价为：

```text
total = price_per_second × duration_seconds
```

新流程只匹配 `model_id IS NULL` 的平台售价，不绑定承运商、模型、供应商或执行类型。普通 5、10、15 秒选项不需要复制同单价规则；固定包、阶梯价和实际输出时长结算须另立合同，不在当前实现中推定存在。

### 3.9 消费订单与任务快照

`task_quotes` 是旧版本短时报价表，仅为已部署历史数据保留，不属于当前直链路预估/提交合同。旧 `POST /client/tasks/quote` 返回 `410 LEGACY_QUOTE_DISABLED`；当前客户端不得提交可篡改的 `priceSnapshot`、`route` 或供应商信息。

预估不创建持久记录，不返回有效期凭证，也不锁定执行配置。`consumption_orders` 保存用户、任务、请求 ID、最终金额、币种、状态与售价/成本/执行快照；`(user_id, client_request_id)` 唯一。订单状态为 `paid`、`refunded`、`failed`。

`generation_tasks` 在创建时保存模式/模型公开 ID、输出参数，以及以下快照：

```text
retail_snapshot
cost_snapshot
offering_snapshot
input_snapshot
execution_snapshot
```

当前没有独立的 `mode_snapshot` / `model_snapshot` 列。`execution_snapshot` 是新任务执行依据；`offering_snapshot` 等字段仍承载历史兼容。内部快照可包含供应商编码和上游标识，仅管理端与 Worker 可读。客户端返回模式、承运商、模型、参数、真实状态、用户消费/退款金额、保存位置和鉴权交付地址。

## 4. 客户端体验和接口合同

### 4.1 创作页

创作页使用三个固定模式的分段控件。模式确定输入区：

| 模式 | 输入区 |
| --- | --- |
| 文生视频 | 提示词 |
| 首尾帧生成视频 | 提示词、首帧、尾帧 |
| 多图生成视频 | 提示词、1 至 N 张参考图片 |

模型区使用“智能推荐”作为默认选项，并提供承运商筛选和模型列表。界面只展示承运商名、模型名、简介、能力标签和对应售价，不显示供应商或“路线”。

通用设置只有：视频时长、输出分辨率、画幅比例、自动生成音频。选择模型后，接口返回该模型和模式的参数可用交集；未选择模型时，返回当前可推荐模型的可用参数。前端不得硬编码 10 秒、1080P 或音频开关为全量可用。

当没有可用供给时：

- 某模型置灰并显示“暂不可用”，但不显示渠道原因。
- 某参数组合不出现在选项中。
- 创建前由服务端再次校验，避免前端缓存导致错误报价。

### 4.2 获取创作目录

```http
GET /api/v1/client/create/catalog
```

响应包含固定模式、对用户可见的承运商与模型、模式模型策略、参数能力和默认值。它不包含供应商、成本、上游工作流 ID、供应商优先级或健康细节。

建议的关键响应形状：

```json
{
"modes": [{ "id": "mode_text", "inputType": "text", "name": "文生视频", "enabled": true }],
  "carriers": [{ "id": "car_minimax", "name": "MiniMax" }],
  "models": [{
    "id": "mdl_h3",
    "carrierId": "car_minimax",
    "name": "H3",
    "inputTypes": ["text", "first_last", "multi_image"]
  }]
}
```

参数能力随 `modeId` 和可选 `modelId` 查询，或由该目录内的能力对象提供。前端只能把它当作展示和初步校验；服务端是唯一权威。

### 4.3 费用预估

```http
POST /api/v1/client/tasks/estimate
```

```json
{
  "modeId": "multi_image_to_video",
  "modelId": "mdl_h3",
  "durationSec": 10,
  "resolution": "1080P",
  "aspectRatio": "9:16",
  "generateAudio": true
}
```

`carrierId` 和 `modelId` 可为空，表示由服务端在用户允许的范围内选择。服务端返回已选中的承运商和模型、当前对客单价和预估总价；预估不创建 quote、订单或任务，也不锁定执行配置：

```json
{
  "selection": {
    "carrier": { "id": "car_minimax", "name": "MiniMax" },
    "model": { "id": "mdl_h3", "name": "H3" }
  },
  "billing": {
    "currency": "CNY",
    "pricePerSecond": 0.50,
    "durationSec": 10,
    "estimatedTotal": 5.00
  }
}
```

响应不得包含成本、供应商、供给 ID、上游工作流 ID 或路由选择理由。

### 4.4 创建任务

```http
POST /api/v1/client/tasks
```

```json
{
  "modeId": "multi_image_to_video",
  "modelId": "mdl_h3",
  "durationSec": 10,
  "resolution": "1080P",
  "aspectRatio": "9:16",
  "generateAudio": true,
  "title": "雨夜街道",
  "prompt": "镜头缓慢向前推进……",
  "sourceMeta": {
    "refs": [{ "type": "asset", "id": "ast_1" }]
  }
}
```

提交接口接收完整创作参数和素材引用，不接收客户端价格快照、供应商、执行类型、工作流编码或成本。客户端应通过 `Idempotency-Key` 请求头或 `clientRequestId` 提供幂等标识。

服务端在一个数据库事务内执行：

1. 锁定用户与请求 ID 的幂等事务边界，查询原订单；已存在则返回原订单与任务，不再路由。
2. 首次请求按模式、承运商、模型和能力重新筛选 API/workflow；按供应商成本、priority、稳定 ID 排序。
3. 校验素材归属、输入、执行凭据和存储；`SELECT ... FOR UPDATE` 锁定钱包并校验余额。
4. 创建消费订单、任务和不可变售价/成本/执行快照，扣减余额并写入钱包流水；中途异常全部回滚。
5. 提交事务后，Worker 按任务快照异步提交上游。无需比较估价与提交结果，以本次提交计算出的价格为准。

余额不足返回 `402 INSUFFICIENT_BALANCE`；空画面描述返回 `400 PROMPT_REQUIRED`；能力组合错误返回 `400 UNAVAILABLE_COMBINATION`；存储与凭据不可用使用稳定的服务不可用错误，不回传内部详情。幂等重放不因后续供给下线而失败。具体响应以 [客户端创作](./api/client-create.md) 为准。

## 5. 路由、计价与执行策略

### 5.1 路由筛选

预估和提交使用同一套路由筛选：

1. 模式已上架，所选或推荐模型已启用。
2. 命中模式模型策略，且模型至少有活跃供给。
3. 供应商/绑定/执行配置启用、健康和额度可用，满足时长、分辨率、画幅、图片数量和音频；适配器已实现，凭据可取得。
4. 命中当前时间窗口和生效区间内的供应商成本规则。
5. 命中同一模式、分辨率、音频组合的有效平台售价规则。
6. API 和 workflow 同时参与候选，按供应商成本升序、priority 升序、稳定 ID 升序选择唯一执行配置；提交前再次检查存储与凭据。

目录/选项是可展示候选，估价/提交还会验证实际凭据和存储。数据库故障不能伪装成“无供给”；无匹配与查询失败必须区分。当前只有经过实现验证的 Adapter 才可被选择。

如果用户明确选择模型，不能悄悄改用其他模型；没有可用供给时应估价失败。“智能推荐”当前选取目录推荐模型后再校验具体参数，边界见 3.4，不承诺自动跨模型寻找可用组合。

### 5.2 预扣与结算

首期三种模式的结算基础是请求时长：

```text
用户预扣 = 平台每秒售价 × 请求秒数
预计成本 = 供应商每秒成本 × 请求秒数
```

上游返回的实际时长用于监控、对账和质量分析，不改变用户首期已支付金额。供应商成本和平台售价都以任务快照为准，后续调价只影响新的预估和提交。

### 5.3 失败、取消和重试

| 场景 | 首期处理 |
| --- | --- |
| 上游提交前取消 | 仅允许取消符合服务端状态条件的任务；已扣费用幂等退款，无报价需要释放 |
| 上游终态失败 | 全额退款，写入退款流水和失败原因 |
| 上游成功 | 不再重新路由，不追加扣费 |
| 用户重试 | 重新预估并提交新任务，按提交时价格重新预扣 |
| 提交结果不明确 | `SUBMIT_UNKNOWN`，暂停自动提交与退款，进入带审计的核对恢复 |
| 上游成功但存储未就绪 | 显示等待交付，按存储恢复/超时规则处理，不伪装已交付 |
| 运营补偿 | 通过显式补偿流水实现，不把“免费重试”隐藏在普通重试里 |

自动故障切换不属于首期。任务一旦预扣并写入供给快照，Worker 不得自动切到另一模型或另一供应商。核对操作用于关联已存在的上游任务或确认拒绝，不得直接重提不确定任务；用户重新生成需要明确创建新的请求。

### 5.4 Worker 执行

Worker 读取任务快照中的 `adapter_code` 和上游工作流 ID，完成：

1. 校验和上传图片素材到对象存储，生成上游可访问 URL。
2. 按 Adapter 将统一参数转换为供应商参数。
3. 取得提交租约后提交并保存上游任务 ID；可能已受理的错误进入待核对，不按所有 4xx 一律退款。
4. 轮询结果、保存成片地址、记录供应商状态和时延。
5. 明确失败时幂等退款；租约失效的旧 Worker 不能覆盖新状态。提交/轮询事件、deadline、poll 次数和下次轮询时刻持久化，以支持恢复。

Adapter 是供应商私有边界。`MapResolutionToUpstream` 等 AutoDL 映射必须移入 `autodl_h3_v1` Adapter；通用报价和任务域只使用 `480P`、`768P`、`1080P` 等标准枚举。

## 6. 管理端信息架构

### 6.1 工作流

“工作流”只展示三个系统工作流及其上架状态、客户端名称、说明和排序。页面不提供新增或删除，也不关联模型、供应商、成本或上游执行标识。

### 6.2 承运商

“承运商”使用原厂和其模型的两层列表，支持新增、编辑、停用/启用。模式模型策略维护启停、推荐顺序、默认时长与分辨率，不绑定售价；内部编码稳定且不由显示名称推导。

### 6.3 供应商

“供应商”分为供应商、API、workflow 三个 tab。供应商目录维护调用地址与只写凭据、供应商模型绑定；执行列表按承运商/模型筛选，维护模式、上游编码、Adapter、能力、状态和成本。原厂模型能力与采购渠道的实际能力分开表达。

### 6.4 价格审计

“价格审计”维护当前按模式、分辨率、自动音频定义的平台每秒售价、版本与状态；历史绑定模型的价格只读且不参与新流程。供应商成本在供应商执行配置中维护，不能混入平台售价。

### 6.5 权限和审计

以下动作必须写入操作日志：

- 承运商、模型、模式模型策略的创建、更新、停用。
- 供应商凭据变更、供给启停、能力变更和成本调价。
- 平台售价发布、下架和版本切换。
- 管理员对失败任务的退款、补偿和重试。

供应商密钥只允许写入，不允许 API 原样读回；管理端只显示“已配置”。

## 7. 历史兼容边界

早期 `platform_workflows` 将模型直接绑定工作流，`supplier_routes` 混合能力与成本，`pricing_rules` 只按工作流和分辨率定价。这些不是当前正式创作路径。以下是已经进入迁移历史的演进说明，不得据此在现有环境重跑历史迁移或重建表。

历史演进顺序：

1. 新增 `creation_modes`，写入三个固定模式。
2. 新增 `mode_model_policies`，将现有 H3 工作流映射到对应模式并设置推荐顺序。
3. 新增 `supplier_offerings` 和 `supplier_cost_rules`，把每条现有 `supplier_routes` 拆为供给与分时段成本。
4. 新增 `retail_price_rules`，将现有 `pricing_rules` 按模式、分辨率、音频开关回填；默认 `generate_audio = false`。
5. 给 `generation_tasks` 添加模式、音频开关、双价格与供给快照字段；新流程的预估不创建报价记录。
6. 暂时保留旧表和旧报价记录供历史读取；所有新预估和新任务只读新结构。
7. 012 起引入模型绑定、统一执行配置和消费订单；020 收敛执行成本唯一约束，021 增加任务租约、截止时间、轮询与事件字段。
8. 旧业务函数和 offering 桥接仍有待逐项隔离。删除前必须确认调用者、历史快照和存量记录需求，不以旧名字为由直接删表。

所有迁移需幂等，数据回填要保留现有任务的供应商、模型、价格和路由快照，不重算旧任务。

## 8. 验收标准

### 8.1 客户端

- 仅显示三种固定创作模式。
- 能按承运商筛选并选择模型；客户端任何响应和页面都不出现供应商名称。
- 选择 H3、10 秒、1080P、自动音频时，只有存在完全匹配供给与售价规则才允许报价。
- 用户选择具体模型后，后端不会改用另一模型；智能推荐时返回最终选中的模型。
- 供应商下线、参数不支持或自动音频无能力时，前端不显示组合且服务端也拒绝报价。

### 8.2 计费和任务

- 同一用户、同一请求 ID 的顺序或并发重放只扣一次，并返回原订单与任务；首次提交后停用供给也不影响重放。
- 调整平台售价或供应商成本后，新的预估和提交使用新版本；历史任务金额不变。
- 任务创建与钱包扣款、流水、订单创建和执行快照写入在同一事务内完成。
- 允许取消或明确上游失败时全额退款且幂等；待核对提交不能自动退款。用户确认重新生成才创建新的请求、任务和流水。
- Worker 使用任务锁定的供给和 Adapter，不读取“当前最低成本路由”重新选择。

### 8.3 安全与可观测性

- 客户端 API、浏览器网络响应、错误信息和任务列表不泄露供应商、成本、Token、上游 URL 或工作流 ID。
- 管理端可追溯每个任务的模式、模型、供应商供给、售价版本、成本版本和上游状态。
- 供应商能力、成本或健康状态变更有审计日志。

## 9. 当前待接入项

1. 每项已启用的音频供给都必须配置经验证的上游参数映射；自动音频无需参考音频，用户上传的参考音频仅在该素材存在时传给上游。
2. 火山引擎的具体模型编码、工作流参数、价格和音频能力需以正式供应商文档为准后再创建供给。
3. 实际输出时长计费、多段音频、动作迁移、视频再生成均不属于当前三模式第一期，需要独立输入合同和结算策略。
