# 创作模式、模型选择与供应商路由设计

## 1. 文档目的

本文定义 Sub2Video 视频生成的产品合同、后台供给模型、报价预扣逻辑和任务执行边界。它用于替代当前“平台工作流直接绑定单个模型、供应商路由同时承载能力与成本”的简化模型。

目标是同时满足以下要求：

1. 客户端永久只提供三种创作模式，不把供应商、渠道、工作流 ID 或成本暴露给创作者。
2. 创作者可以选择承运商和模型；未选择时由平台按明确的推荐策略选择模型。
3. 同一个模型可以由官方和多个第三方供应商供给，平台能在不改变用户模型选择的前提下选择合适的供应商。
4. 供应商成本与平台对客售价独立维护；创建任务时同时固化两类价格和执行路由。
5. 时长按秒作为计费数量。只有供应商存在固定套餐或时长阶梯折扣时，才需要额外的时长价格规则。

本文不设计面向客户的 API Key、供应商账户、渠道余额或代理管理功能。

## 2. 已确认的产品决定

### 2.1 客户端模式固定为三种

| 模式代码 | 客户端名称 | 必填输入 | 不变约束 |
| --- | --- | --- | --- |
| `text_to_video` | 文生视频 | 提示词 | 不上传图片 |
| `first_last_frame_to_video` | 首尾帧生成视频 | 提示词、首帧图片、尾帧图片 | 首尾帧均必填 |
| `multi_image_to_video` | 多图生成视频 | 提示词、至少一张参考图 | 图片上限由模型供给定义 |

这三个模式是系统产品合同，不允许管理员新增第四种客户端模式，也不允许将上游工作流名称直接作为模式。管理员只能上架、下架、排序和配置每个模式可使用的模型。

### 2.2 模型选择对用户可见，供应商对用户不可见

客户端的选择顺序为：

```text
创作模式
  -> 承运商（可选筛选）
  -> 模型（可选；默认智能推荐）
  -> 视频时长 / 分辨率 / 画幅 / 自动生成音频
  -> 报价
  -> 提交
```

承运商是模型原厂，例如 MiniMax、火山引擎。模型是原厂的具体型号，例如 H3、Seedance 2.0、Seedance 2.5。供应商是实际采购和调用渠道，例如官方 MiniMax、官方火山引擎、AutoDL；它只存在于管理端和后端。

模型选择不是第四个创作模式。一个模型可以同时支持文生视频、首尾帧和多图生成，用户在模式内选择模型只是表达质量、风格或能力偏好。

### 2.3 自动生成音频的定义

首期“是否需要音频”表示**要求模型自动生成视频音频**，不接收参考音频素材。请求字段使用 `generateAudio`。

已调研的 AutoDL H3 音频工作流主要是“上传参考音频并做音画同步”，不能当作自动生成音频能力。只有供应商供给明确声明 `supports_generated_audio = true`，并存在对应的上游参数映射时，客户端才可显示和选择此开关。否则该模式和模型下不显示该选项，服务端报价也必须拒绝该组合。

参考音频属于未来独立能力，不复用 `generateAudio`，届时新增 `audio_input` 输入合同和专门的模式/供给能力字段。

## 3. 目标领域模型

```text
创作模式 1 --- N 模式模型策略 N --- 1 模型 N --- 1 承运商
                                  |
                                  | 作为请求约束
                                  v
供应商 1 --- N 供应商供给 N --- 1 模型
                         |
                         + --- 1 创作模式
                         + --- N 供应商成本规则

模式 + 模型 + 输出参数 --- 平台售价规则

报价 --- 固化：模型、供给、售价、成本、输入参数
任务 --- 消费报价并生成不可变执行快照
```

### 3.1 创作模式 `creation_modes`

该表只保存三个系统种子数据，`code` 受服务端白名单约束。管理员页面只能编辑展示名称、说明、排序和上架状态，不能创建或删除模式。

| 字段 | 说明 |
| --- | --- |
| `id` / `public_id` | 内部和对外标识 |
| `code` | 三个固定模式代码之一 |
| `name` / `description` | 客户端展示文案 |
| `status` | `published`、`disabled` |
| `sort_order` | 客户端排序 |
| `input_contract` | 系统生成的只读输入合同快照，用于审计和接口返回 |

`input_contract` 不接受管理员自由编辑，以避免页面控件与后端校验分叉。输入校验以模式代码的服务端实现为准。

### 3.2 承运商 `carriers`

承运商代表模型原厂，可新增、查询、编辑和停用/启用。首批种子为 MiniMax 和火山引擎。有历史任务引用时只允许停用，不物理删除。

### 3.3 模型 `models`

模型归属一个承运商，可新增、查询、编辑和停用/启用。模型只描述原厂型号，不携带某个供应商工作流 ID，也不再使用单值 `client_workflow_id`，因为一个模型可支持多个创作模式和多个供应商供给。

| 字段 | 说明 |
| --- | --- |
| `carrier_id` | 模型原厂 |
| `code` | 稳定机器编码，如 `h3`、`seedance_2_0` |
| `name` / `description` | 管理端和客户端展示 |
| `enabled` | 是否允许新建供给和展示给用户 |
| `sort_order` | 同承运商下的排序 |

模型不能因为某个供应商下线而直接消失。客户端仅在该模型存在至少一个可报价的供给时显示为可用。

### 3.4 模式模型策略 `mode_model_policies`

该表连接创作模式和模型，控制哪些模型可用于某个模式，以及未选择模型时的推荐顺序。

| 字段 | 说明 |
| --- | --- |
| `mode_id` / `model_id` | 唯一组合 |
| `enabled` | 是否允许客户端主动选择 |
| `recommendation_rank` | 智能推荐时从小到大选择 |
| `display_badge` | 可选客户端角标，如“推荐”“高质量” |
| `default_resolution` / `default_duration` | 仅作默认值，必须在可用供给范围内 |

“智能推荐”严格按 `recommendation_rank` 选择第一个满足当前输入参数且有活跃供给的模型；不会为了更低采购成本在不同模型之间随意切换。选定模型后，才在该模型的供应商供给中按成本选择渠道。

### 3.5 供应商 `suppliers`

供应商代表采购渠道，维护连接信息、凭据、健康状态和运营状态。凭据必须加密保存，任何客户端 API、前端 bundle、任务列表、报价响应都不能返回供应商名称、编码、成本、连接地址或上游工作流 ID。

官方渠道与第三方渠道使用相同模型：官方 MiniMax、官方火山引擎均是供应商记录，并不拥有特殊的客户端展示权限。

### 3.6 供应商供给 `supplier_offerings`

供应商供给是唯一可被 Worker 执行的路由单元，替代当前概念含混的 `supplier_routes`。一条供给表示“供应商 S 可以使用模型 M 完成模式 P，并映射到其上游工作流”。

| 字段 | 说明 |
| --- | --- |
| `supplier_id` / `model_id` / `mode_id` | 采购渠道、模型和客户端模式 |
| `upstream_workflow_id` | 仅后端使用的供应商工作流 ID |
| `adapter_code` | 参数与结果转换器，例如 `autodl_h3_v1` |
| `enabled` / `health_status` | 是否参与新报价；健康异常立即排除 |
| `priority` | 同成本供给的运营优先级 |
| `min_duration_sec` / `max_duration_sec` | 可接受的时长范围 |
| `resolutions` | 支持的标准分辨率，如 `480P`、`768P`、`1080P` |
| `aspect_ratios` | 支持的画幅比例 |
| `min_images` / `max_images` | 多图模式的图像范围；其他模式为 0 |
| `supports_generated_audio` | 是否可无参考音频地生成音频 |
| `parameter_mapping` | 供应商私有字段映射，仅供 Adapter 使用 |

同一供应商、模型和模式可以有多条供给，例如不同上游工作流分别覆盖 10 秒 1080P 自动音频和 15 秒 768P 无音频。唯一性应至少包含 `supplier_id`、`model_id`、`mode_id`、`upstream_workflow_id`。

### 3.7 供应商成本规则 `supplier_cost_rules`

成本必须属于供应商供给，不属于模型，也不属于客户端模式。标准规则的价格粒度为每秒。

| 字段 | 说明 |
| --- | --- |
| `offering_id` | 对应供应商供给 |
| `resolution` | 输出分辨率 |
| `generate_audio` | 自动音频开关 |
| `price_per_second` | 采购成本单价 |
| `time_window` | 时段，例如 `00:00-08:00`、`08:00-24:00` |
| `effective_from` / `effective_to` | 合同价格生效区间 |
| `currency` | 首期固定 `CNY` |
| `status` | `active`、`draft`、`expired` |

对于“按实际输出时长收费”的供应商，供给需要声明 `billing_basis = actual_output_duration`。首期三种视频模式只上架 `requested_duration` 计费的供给；实际时长计费在支持前必须增加预授权、最终结算和差额退款流程，不能复用现有预扣逻辑。

### 3.8 平台售价规则 `retail_price_rules`

用户可见的售价独立于供应商成本，主键为：

```text
创作模式 × 模型 × 分辨率 × 是否自动生成音频 × 价格版本
```

| 字段 | 说明 |
| --- | --- |
| `mode_id` / `model_id` | 用户最终选择或平台推荐的产品能力 |
| `resolution` / `generate_audio` | 输出参数 |
| `price_per_second` | 对客单价 |
| `version` | 报价和任务快照使用的不可变版本 |
| `status` | `active`、`draft`、`disabled` |
| `effective_from` / `effective_to` | 调价生效区间 |

时长不在规则唯一键中。标准总价为：

```text
total = price_per_second × duration_seconds
```

供应商有固定包或阶梯价时，新增可选的 `duration_min`、`duration_max` 字段，并要求任意参数组合最多命中一条有效规则。不要为普通 5、10、15 秒选项复制三条同单价规则。

### 3.9 报价和任务快照

`task_quotes` 是短时有效、一次性使用的服务器报价，建议有效期 5 分钟。客户端不得再提交可篡改的 `priceSnapshot`、`route` 或供应商信息。

报价至少记录：用户、规范化请求参数、选定承运商/模型、供应商供给 ID、售价规则版本、成本规则版本、每秒售价、每秒成本、总售价、预计总成本、创建时间、过期时间和使用时间。

`generation_tasks` 在创建时保存以下不可变快照：

```text
mode_snapshot
model_snapshot
retail_snapshot
cost_snapshot
offering_snapshot
input_snapshot
```

其中 `offering_snapshot` 可包含供应商编码和上游工作流 ID，但仅管理端和 Worker 可读；客户端任务响应只返回模式、承运商、模型、参数、状态和用户实际支付金额。

## 4. 客户端体验和接口合同

### 4.1 创作页

创作页使用三个固定模式的分段控件。模式确定输入区：

| 模式 | 输入区 |
| --- | --- |
| 文生视频 | 提示词 |
| 首尾帧生成视频 | 提示词、首帧、尾帧 |
| 多图生成视频 | 提示词、1 至 N 张参考图片 |

模型区使用“智能推荐”作为默认选项，并提供承运商筛选和模型列表。界面只展示承运商名、模型名、简介、能力标签和对应售价，不显示供应商或“路线”。

通用设置只有：视频时长、输出分辨率、画幅比例、自动生成音频。选择模型后，接口返回该模型和模式的参数可用交集；未选择模型时，返回当前可推荐模型的可用参数。前端不得硬编码 10 秒、1080P 或音频开关为全量可用。

当没有可用供给时：

- 某模型置灰并显示“暂不可用”，但不显示渠道原因。
- 某参数组合不出现在选项中。
- 创建前由服务端再次校验，避免前端缓存导致错误报价。

### 4.2 获取创作目录

```http
GET /api/v1/client/create/catalog
```

响应包含固定模式、对用户可见的承运商与模型、模式模型策略、参数能力和默认值。它不包含供应商、成本、上游工作流 ID、供应商优先级或健康细节。

建议的关键响应形状：

```json
{
  "modes": [{ "id": "text_to_video", "name": "文生视频", "enabled": true }],
  "carriers": [{ "id": "car_minimax", "name": "MiniMax" }],
  "models": [{
    "id": "mdl_h3",
    "carrierId": "car_minimax",
    "name": "H3",
    "modes": ["text_to_video", "first_last_frame_to_video", "multi_image_to_video"]
  }]
}
```

参数能力随 `modeId` 和可选 `modelId` 查询，或由该目录内的能力对象提供。前端只能把它当作展示和初步校验；服务端是唯一权威。

### 4.3 报价

```http
POST /api/v1/client/tasks/quote
```

```json
{
  "modeId": "multi_image_to_video",
  "modelId": "mdl_h3",
  "durationSeconds": 10,
  "resolution": "1080P",
  "aspectRatio": "9:16",
  "generateAudio": true
}
```

`modelId` 可为空，表示智能推荐。服务端返回已选中的承运商和模型、可见售价、总价、报价 ID 与过期时间：

```json
{
  "quoteId": "qt_01...",
  "expiresAt": "2026-09-04T08:05:00Z",
  "selection": {
    "carrier": { "id": "car_minimax", "name": "MiniMax" },
    "model": { "id": "mdl_h3", "name": "H3" }
  },
  "price": {
    "currency": "CNY",
    "pricePerSecond": 0.50,
    "durationSeconds": 10,
    "total": 5.00
  }
}
```

响应不得包含成本、供应商、供给 ID、上游工作流 ID 或路由选择理由。

### 4.4 创建任务

```http
POST /api/v1/client/tasks
```

```json
{
  "quoteId": "qt_01...",
  "title": "雨夜街道",
  "prompt": "镜头缓慢向前推进……",
  "sourceMeta": {
    "first": { "type": "asset", "id": "ast_1" },
    "last": { "type": "upload", "id": "upl_2" }
  }
}
```

创建接口不再接收 `workflowId`、`modelId`、`resolution`、`durationSeconds` 或客户端价格快照。这些内容必须来自未过期且未使用的 `quoteId`，避免参数与价格被调包。

服务端在一个数据库事务内执行：

1. 锁定报价并校验用户、有效期、未使用状态和请求素材归属。
2. 再次确认选定供给、售价规则和成本规则仍可执行；失效则返回 `409 QUOTE_EXPIRED_OR_UNAVAILABLE`，要求重新报价。
3. `SELECT ... FOR UPDATE` 锁定钱包并校验余额。
4. 创建任务、写入所有快照、扣减余额、写入钱包流水、标记报价已使用。
5. 提交事务后，Worker 按任务快照异步提交上游。

余额不足返回 `402 INSUFFICIENT_BALANCE`；参数与素材不符返回 `400 INVALID_TASK_INPUT`；报价已过期、已使用或供给已下线返回 `409`。

## 5. 路由、计价与执行策略

### 5.1 路由筛选

报价服务按以下顺序筛选：

1. 模式已上架，所选或推荐模型已启用。
2. 命中模式模型策略，且模型至少有活跃供给。
3. 供给已启用、健康状态为可用，且满足时长、分辨率、画幅、图片数量和自动音频条件。
4. 命中当前时间窗口和生效区间内的供应商成本规则。
5. 命中同一模式、模型、分辨率、音频组合的有效平台售价规则。
6. 在**同一模型**候选中按当前每秒成本升序、供给优先级升序、稳定 ID 升序选择唯一供给。

如果用户明确选择模型，不能悄悄改用其他模型；没有可用供给时应报价失败。只有选择“智能推荐”时，才按 `mode_model_policies.recommendation_rank` 找到第一个满足条件的模型。

### 5.2 预扣与结算

首期三种模式的结算基础是请求时长：

```text
用户预扣 = 平台每秒售价 × 请求秒数
预计成本 = 供应商每秒成本 × 请求秒数
```

上游返回的实际时长用于监控、对账和质量分析，不改变用户首期已支付金额。供应商成本和平台售价都以任务快照为准，后续调价只影响新报价。

### 5.3 失败、取消和重试

| 场景 | 首期处理 |
| --- | --- |
| 上游提交前取消 | 释放报价或取消任务；若已预扣则全额退款 |
| 上游终态失败 | 全额退款，写入退款流水和失败原因 |
| 上游成功 | 不再重新路由，不追加扣费 |
| 用户重试 | 创建新报价和新任务，按当时价格重新预扣 |
| 运营补偿 | 通过显式补偿流水实现，不把“免费重试”隐藏在普通重试里 |

自动故障切换不属于首期。任务一旦预扣并写入供给快照，Worker 不得自动切到另一模型或另一供应商；需要改路由时由管理员显式重试并保留审计记录。

### 5.4 Worker 执行

Worker 读取任务快照中的 `adapter_code` 和上游工作流 ID，完成：

1. 校验和上传图片素材到对象存储，生成上游可访问 URL。
2. 按 Adapter 将统一参数转换为供应商参数。
3. 提交任务并保存上游任务 ID。
4. 轮询结果、保存成片地址、记录供应商状态和时延。
5. 失败时转入退款流程，不执行未审计的自动换供应商。

Adapter 是供应商私有边界。`MapResolutionToUpstream` 等 AutoDL 映射必须移入 `autodl_h3_v1` Adapter；通用报价和任务域只使用 `480P`、`768P`、`1080P` 等标准枚举。

## 6. 管理端信息架构

### 6.1 创作模式

保留现有“工作流”菜单位置，但页面名称调整为“创作模式”。展示三个系统模式、上架状态、可选模型、默认模型策略和对客售价概览。页面不提供新增模式按钮。

### 6.2 承运商与模型

在“模型与供应商”下分为两个独立页签：

1. **承运商与模型**：维护原厂、模型和模式模型策略；不填写 Token、成本或上游工作流。
2. **供应商供给**：维护供应商、凭据、供给能力、上游工作流 ID、健康状态和采购成本规则。

将成本、凭据和上游工作流放在供应商供给页，可避免误把“模型 H3 的能力”与“某渠道销售 H3 的能力”混淆。

### 6.3 定价规则

“定价规则”页面仅维护平台对客售价，行维度为：模式、模型、分辨率、自动音频、每秒售价、版本、生效时间和状态。页面可以展示成本毛利率范围供管理员参考，但不向客户端暴露。

供应商成本规则在供应商供给详情内维护，避免在一个表格里把进货成本和销售价格混在一起。

### 6.4 权限和审计

以下动作必须写入操作日志：

- 承运商、模型、模式模型策略的创建、更新、停用。
- 供应商凭据变更、供给启停、能力变更和成本调价。
- 平台售价发布、下架和版本切换。
- 管理员对失败任务的退款、补偿和重试。

供应商密钥只允许写入，不允许 API 原样读回；管理端只显示“已配置”。

## 7. 从当前实现迁移

当前 `platform_workflows` 将 `model_id` 直接绑定在工作流上，`supplier_routes` 同时承载能力条件和高低峰成本，`pricing_rules` 只按工作流和分辨率售价。它们不能表达用户可选模型和自动生成音频。

迁移必须新增表并回填，而不是修改历史任务的快照：

1. 新增 `creation_modes`，写入三个固定模式。
2. 新增 `mode_model_policies`，将现有 H3 工作流映射到对应模式并设置推荐顺序。
3. 新增 `supplier_offerings` 和 `supplier_cost_rules`，把每条现有 `supplier_routes` 拆为供给与分时段成本。
4. 新增 `retail_price_rules`，将现有 `pricing_rules` 按模式、模型、分辨率回填；默认 `generate_audio = false`。
5. 新增 `task_quotes`，并给 `generation_tasks` 添加模式、音频开关、报价 ID和双价格/供给快照字段。
6. 暂时保留旧表供历史读取；所有新报价和新任务只读新结构。
7. 完成历史数据校验和后台迁移后，再移除旧代码路径和废弃字段。

所有迁移需幂等，数据回填要保留现有任务的供应商、模型、价格和路由快照，不重算旧任务。

## 8. 验收标准

### 8.1 客户端

- 仅显示三种固定创作模式。
- 能按承运商筛选并选择模型；客户端任何响应和页面都不出现供应商名称。
- 选择 H3、10 秒、1080P、自动音频时，只有存在完全匹配供给与售价规则才允许报价。
- 用户选择具体模型后，后端不会改用另一模型；智能推荐时返回最终选中的模型。
- 供应商下线、参数不支持或自动音频无能力时，前端不显示组合且服务端也拒绝报价。

### 8.2 计费和任务

- 同一报价重复提交只能成功一次。
- 调整平台售价或供应商成本后，旧报价按过期策略失效，新报价使用新版本；历史任务金额不变。
- 任务创建与钱包扣款、流水、报价消费在同一事务内完成。
- 失败任务全额退款；重试创建独立的报价、任务和流水。
- Worker 使用任务锁定的供给和 Adapter，不读取“当前最低成本路由”重新选择。

### 8.3 安全与可观测性

- 客户端 API、浏览器网络响应、错误信息和任务列表不泄露供应商、成本、Token、上游 URL 或工作流 ID。
- 管理端可追溯每个任务的模式、模型、供应商供给、售价版本、成本版本和上游状态。
- 供应商能力、成本或健康状态变更有审计日志。

## 9. 当前待接入项

2. 火山引擎的具体模型编码、工作流参数、价格和自动音频能力需以正式供应商文档为准后再创建供给。
3. 实际输出时长计费、参考音频、多段音频、动作迁移、视频再生成均不属于当前三模式第一期，需要独立输入合同和结算策略。
