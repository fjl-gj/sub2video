# Sub2Video 后台服务架构

本文件描述当前实现和已确认的演进边界，不再保留 SQLite、chi 或“前端尚未接 API”的历史假设。产品语义见 [产品方案总览](../产品方案总览.md)，创作供给与计费合同见 [创作模式与供应商路由设计](../创作模式与供应商路由设计.md)。

## 当前实现

| 层 | 实现 |
| --- | --- |
| HTTP | Go + Gin，`backend/internal/server` |
| 数据库 | PostgreSQL + pgx，SQL 迁移位于 `backend/migrations` |
| 身份认证 | JWT、登录/注册/刷新、角色校验 |
| 钱包 | PostgreSQL 事务锁定、余额流水、任务预扣与退款 |
| 文件 | 本地上传元数据；MinIO/COS 对象存储抽象用于上游可访问素材和结果 |
| 异步执行 | 内置 Worker 轮询任务；AutoDL H3 Adapter 已接入 |
| 供给 | 承运商、模型、供应商、供应商供给、成本规则和售价规则 |

```text
Browser
  │ /api/v1
  ▼
Gin API ──────────────── PostgreSQL
  │                         ├─ users / wallets / wallet_ledger
  │                         ├─ creation_modes / models / suppliers
  │                         ├─ supplier_model_bindings / supplier_executions
  │                         ├─ supplier_cost_rules / retail_price_rules
  │                         └─ consumption_orders / generation_tasks
  ├─ Object Storage (MinIO / COS)
  └─ Worker → Adapter → upstream supplier
```

## 创作与报价

`creation_modes` 只允许三个种子模式。`mode_model_policies` 定义模式内可选模型和智能推荐顺序。承运商是模型原厂；供应商是实际采购渠道。正式路由单元是 `supplier_executions`，通过 `supplier_model_bindings` 关联供应商与模型；`supplier_cost_rules.execution_id` 维护采购成本。平台售价只按模式、分辨率、自动音频选择 `retail_price_rules` 中 `model_id IS NULL` 的规则。

```text
POST /client/tasks/estimate
  → 校验模式/模型/参数
  → 确定模型（明确选择或推荐顺序）
  → 在同一模型的可用供给中按成本、优先级、稳定 ID 选择
  → 返回当前平台售价（不写报价、任务、订单，不扣费）

POST /client/tasks + 幂等请求 ID
  → 事务内检查已有订单，存在则直接返回
  → 首次请求重新路由并计算最终价
  → 校验素材与执行条件，锁钱包
  → 原子写任务、订单、执行/价格快照、扣费与流水
```

预估没有 quoteId、有效期凭证或锁价承诺。调价和供给变化影响首次提交的重新计算，不阻断已有幂等请求的重放。新流程不读写 `task_quotes`；旧 `/client/tasks/quote` 只返回 410。历史表和 offering/route 字段暂留作兼容，不是新业务的权威入口。

代码边界：`direct_routing.go` 负责正式估价与幂等提交；`creation_catalog.go` 负责目录、能力和配置；`legacy_quotes.go` 隔离历史报价类型、TTL 与消费逻辑。共享素材校验只依赖模式与图片数量约束，不再要求临时 `TaskQuote`。管理配置的新旧表写入使用同一事务，数据库故障不能伪装成“没有可用供给”。

## Worker 边界

Worker 对新任务读取锁定的供给 ID、上游工作流和 Adapter，不再执行“当前最低成本路由”选择。Adapter 负责供应商私有参数转换、素材上传、上游提交与结果轮询。新 Adapter 必须显式实现，不能让通用报价层感知供应商工作流 ID。

AutoDL H3 的验收工作流和能力见 [直链路合同](../api/client-direct-routing.md)。API 执行类型已经入模，但未实现的适配器必须从目录、估价和提交中排除，不能借用 workflow 协议伪装 API 可用。已有参考音频是可选素材，不是自动生成音频的前提；本轮不扩展其功能。

提交租约、轮询租约、deadline、重试时刻和供应商事件由任务状态持久化。上游可能已受理而响应丢失、损坏或本地保存失败时，进入 `SUBMIT_UNKNOWN` 核对流程，不自动重提或退款；只有明确失败或被允许取消才进入退款。对象存储等待与最终交付分别表示，不能以拿到上游 URL 代替成片已交付。

## 事务和退款

创建任务的数据库事务包含：

1. 使用用户与请求 ID 的事务锁，查询已有消费订单；存在即返回原结果。
2. 通过事务连接重新路由；校验素材归属、模式合同、凭据和存储。
3. `FOR UPDATE` 锁定钱包并校验余额。
4. 写入任务、消费订单、售价/成本/执行/输入快照，扣款并写 `task_charge` 流水。
5. 提交事务；任一中途失败均回滚，Worker 只消费成功提交的任务。

明确上游终态失败时，Worker 将任务置为失败并写入一次性 `task_refund` 流水。用户明确开始新的生成属于新的请求 ID 和任务；对原提交结果的网络重试必须复用原 ID。不能把已经失败的原任务直接重新排队。

## 运行与演进

- `--migrate-only` 只连接 PostgreSQL、执行迁移并退出，不启动 Worker/HTTP/Redis、不执行 seed。普通启动是否迁移与 seed 由 `SUB2VIDEO_SKIP_BOOTSTRAP` 控制；发布前必须检查实际配置，不能假定启动一定无数据影响。
- 供应商 Token 使用加密字段保存，客户端和管理端读取接口均不回传明文。
- Redis、对象存储是现有运行依赖；在线支付尚未开放。生产部署应将 API、数据库凭据、对象存储凭据和 Worker 监控分别配置。
- 数据库集成测试和管理审计已存在。执行方式、隔离要求与 skip 条件见 [backend/README](../../backend/README.md)；单测通过不代表真实数据库、供应商或交付验收通过。
