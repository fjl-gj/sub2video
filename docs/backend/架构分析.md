# Sub2Video 后台服务架构

本文件描述当前实现和已确认的演进边界，不再保留 SQLite、chi 或“前端尚未接 API”的历史假设。产品语义见 [产品方案总览](../产品方案总览.md)，创作供给与计费合同见 [创作模式与供应商路由设计](../创作模式与供应商路由设计.md)。

## 当前实现

| 层 | 实现 |
| --- | --- |
| HTTP | Go + Gin，`backend/internal/server` |
| 数据库 | PostgreSQL + pgx，SQL 迁移位于 `backend/migrations` |
| 身份认证 | JWT、登录/注册/刷新、角色校验 |
| 钱包 | PostgreSQL 事务锁定、余额流水、任务预扣与退款 |
| 文件 | 本地上传元数据；MinIO/COS 对象存储抽象用于上游可访问素材和结果 |
| 异步执行 | 内置 Worker 轮询任务；AutoDL H3 Adapter 已接入 |
| 供给 | 承运商、模型、供应商、供应商供给、成本规则和售价规则 |

```text
Browser
  │ /api/v1
  ▼
Gin API ──────────────── PostgreSQL
  │                         ├─ users / wallets / wallet_ledger
  │                         ├─ creation_modes / models / suppliers
  │                         ├─ supplier_offerings / cost rules / retail rules
  │                         └─ task_quotes / generation_tasks
  ├─ Object Storage (MinIO / COS)
  └─ Worker → Adapter → upstream supplier
```

## 创作与报价

`creation_modes` 只允许三个种子模式。`mode_model_policies` 定义模式内可选模型和智能推荐顺序。承运商是模型原厂；供应商是实际采购渠道。`supplier_offerings` 是唯一可执行的路由单元，携带上游工作流、能力和 Adapter；`supplier_cost_rules` 只维护采购成本；`retail_price_rules` 只维护对客售价。

```text
客户端请求
  → 校验模式/模型/参数
  → 确定模型（明确选择或推荐顺序）
  → 在同一模型的可用供给中按成本、优先级、稳定 ID 选择
  → 创建五分钟一次性报价
  → 消费报价：锁钱包、写任务快照、扣款、流水、标记已使用
```

报价和任务分别保存售价、成本、供给与输入快照。调价、成本变动、模式/供给停用会使未使用报价不可用；已创建任务不能自动换供应商或模型。

## Worker 边界

Worker 对新任务读取锁定的供给 ID、上游工作流和 Adapter，不再执行“当前最低成本路由”选择。Adapter 负责供应商私有参数转换、素材上传、上游提交与结果轮询。新 Adapter 必须显式实现，不能让通用报价层感知供应商工作流 ID。

AutoDL H3 目前只为确认的 `768P`、无自动生成音频供给种子数据。参考音频不属于 `generateAudio`，不得伪装成自动音频能力。

## 事务和退款

创建任务的数据库事务包含：

1. `FOR UPDATE` 锁定报价，确认用户、有效期、未使用和当前可用性。
2. 校验输入素材归属和模式合同。
3. `FOR UPDATE` 锁定钱包并校验余额。
4. 写入任务及双价格/供给/输入快照，扣款并写 `task_charge` 流水。
5. 消费报价并提交事务。

上游终态失败时，Worker 将任务置为失败并写入一次性 `task_refund` 流水。用户重试属于新的报价和任务，不能把原任务重新排队。

## 运行与演进

- 迁移在服务启动时执行，种子只首次插入，不覆盖运营侧的模式、供给和价格调整。
- 供应商 Token 使用加密字段保存，客户端和管理端读取接口均不回传明文。
- Redis、对象存储和支付已保留接入位置；生产部署应将 API、数据库凭据、对象存储凭据和 Worker 监控分别配置。
- 下一阶段应增加数据库集成测试、管理操作审计日志、供给健康检查和独立队列消费者。
