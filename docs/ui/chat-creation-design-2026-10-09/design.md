# Sub2Video：内容型创作工作台与对话整理

## 2026-10-10 再修订：借鉴小云雀的内容层级

上一版把“聊天”放得太靠前，容易让产品看起来像客服窗口或通用 AI 对话页。根据小云雀实际页面重新收敛后，首屏只保留内容型创作平台最有价值的三层：

1. 左侧导航与作品上下文，让用户知道自己在哪里、有哪些作品可以继续；
2. 大型“开始创作”卡，按“创作方式 → 描述/素材 → 承运商/模型/画幅/时长 → 估价/提交”的顺序完成一镜；
3. 灵感参考与继续创作，帮助用户从一个画面进入下一步，但明确标记为参考示例，不伪装成真实案例。

小云雀只借鉴信息层级、入口密度和“先给创作容器、再给灵感与项目”的产品节奏。Sub2Video 仍保留自己的深色工作区、单镜头模型合同和导演台边界，不复制品牌、菜单、文案或素材。

本次稿件还做了四项收敛：

- 把承运商和模型偏好放回创作卡底部，使用面向创作者的名称，不展示内部 API/workflow 编码；
- 删除没有正式业务字段映射的“风格”选择，避免出现选了风格却没有进入草稿或提交参数的假能力；
- 删除当前未验证的 1:1 画幅，只保留示例中已讨论的 16:9 与 9:16；
- 增加“提交待核对、失败并退款、交付完成”的只读状态示意，并保持不可重复提交；聊天仍是点击“整理镜头”后的二级能力。

这轮仍是本地设计稿，金额、状态、图片、模型选项均为示例，不代表当前 107 可用供给，也不连接真实任务、钱包、作品或供应商。

> 2026-10-10 修订：根据小云雀实际工作台重新调整首屏层级。小云雀只作为信息架构参考，不复制品牌、文案或具体视觉资产。

## 设计判断

采用“对话驱动的创作工作台”是合适的。用户不必先理解全部表单，就可以开始描述和修改镜头。素材、模型、参数、费用与任务仍然保持为独立可核对的对象。

当前项目没有已接通的聊天/LLM 接口。设计稿中的助手回复是明确标注的本地示例，不代表自动理解、提示词优化或导演能力已经实现。首版实现可以先将表达入口与原有创建合同连接，再单独实现可解释、可撤销的对话建议。

只有三种模式：文生视频、首尾帧、多图。Chat 不增加第四种模式，不引入第二套钱包、任务或资产系统，不扩展完整影片工程。

## 信息架构与操作顺序

| 区域 | 用户要完成的事情 | 业务边界 |
| --- | --- | --- |
| 镜头上下文 | 知道正在创作哪一镜；从导演台进入时能返回原作品/镜头 | 普通单镜头也能使用，不强制创建影片工程 |
| 对话 | 描述场景、人物动作、镜头运动；继续提出修改 | 发送或整理不创建生成任务、不扣费 |
| 镜头草稿 | 查看最终采用的描述，而非把全部聊天历史当提示词 | 拟议建议需明确应用；本稿采用本地规则示意 |
| 素材 | 文生不要求图；首尾帧有两个明确槽位；多图至少一张 | 本稿文件只在浏览器预览，不上传 |
| 画面与设置 | 查看参考画面与承运商/模型、时长、分辨率、画幅、音频 | 真实选项来自目录；不静默替换模型 |
| 费用确认 | 查看估价，明确确认生成 | 正式路径仍为 estimate → tasks；提交重新计算，不锁价 |
| 任务与结果 | 知道真实状态，下载、保存作品、再次创作 | 不把参考图片/品牌视频当成新生成结果 |

主操作：描述镜头 → 准备素材 → 核对设置 → 查看费用 → 明确确认生成 → 查看任务/结果。

保留显式模式选择。可以按素材推荐模式，但用户应用之前不自动切换。正式模型偏好继续来自现有目录；原型只展示 MiniMax/H3 的示例，不代表目录当前可用。

## 原型状态与可操作内容

顶部“查看状态”是审阅工具，不属于拟发布产品。

| 状态 | 设计表达 | 本稿可以操作的内容 |
| --- | --- | --- |
| 首次创作 | 给一个画面描述入口和三个具体起点 | 选择例子、填写描述、切换模式 |
| 镜头准备 | 对话、草稿、参考画面与参数并列 | 追加修改、展开描述、本地选择图片、移除素材 |
| 费用确认 | 展示示例金额与独立确认按钮 | 原型估价；修改后清除估价；确认后仅切换原型状态 |
| 执行中 | 保留原提交与预扣状态 | 查看状态说明；修改只用于下一次草稿 |
| 交付示意 | 展示播放器、下载、保存位置和再次创作 | 播放/下载品牌参考视频，查看模拟保存位置 |
| 服务未就绪 | 能继续准备，不暗示刷新可修复配置 | 修改草稿、查看帮助、保留描述与参数；不能估价提交 |
| 失败与退款 | 失败原因与退款金额/时间同时出现 | 查看示意记录，按原任务参数重新准备 |
| 提交待核对 | 明确不要重复生成 | 持续保留状态，查看核对入口，阻止本镜头再次提交 |

原型内金额、账户、回复、退款时间均标注示例。¥0.15 是 `5 秒 × ¥0.03` 的演示数字，不是当前 107 有效估价或商业定价承诺。

修改描述、模式、素材、参数时清除旧估价。这个页面状态失效不是 quote 凭证过期；不产生 quoteId，不写 task_quotes，不引入锁价。

原任务快照与草稿区分。执行中和提交待核对不会被编辑清除；“按原参数创作”回填原任务参数而不自动提交。正式落地仍需现有幂等请求与待核对恢复合同。

## 与导演台的衔接

沿用“资产中的作品 → 导演台镜头 → 既有创作任务”关系。从镜头进入时顶栏应显示原作品/镜头和返回入口，聊天修改针对当前镜头。普通用户仍可以直接创作，不必先进入导演台。

“保留描述与参数”“保存到导演镜头”“付费生成”是不同动作。当前本地 File/blob 不持久化；存储缺失时，导演台保存素材也可能失败，不能演示成总会成功。

本稿“保留草稿”只写浏览器独立 key `s2v-canvas-design-draft-v2`，保存描述、模式、承运商、模型和画幅；刷新恢复时会要求重新选择本地图片。不访问真实任务、作品或钱包。本轮浏览器检查后已经通过重新加载清除了该测试草稿。

正式开发需要补：对话/建议合同（是否调用 LLM、耗时/费用、可撤销应用）、草稿与镜头上下文、跨设备草稿策略、现有目录/素材/估价/提交/任务状态连接，以及相关 Vue/Playwright 回归。本轮不实现这些能力。
