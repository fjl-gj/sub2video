# Sub2Video 创作者五页主链路设计

日期：2026-09-26。此文档记录交互设计与真实合同之间的边界。新版前端与下载续签修复已部署至 107 UAT，已有真实成片播放和下载通过；本轮未创建收费任务，也不代表商业验收完成。分阶段记录见文末。

设计稿：[creator-journey.html](./creator-journey.html)。底部可切换五个视图；首页教程入口、跟做镜头、结果页保存入口与作品内页可连贯操作。支持 `#home`、`#tutorial`、`#create`、`#result`、`#projects` 定位。全部是设计示意，不访问业务 API，不上传、不扣费、不生成任务，不下载，也不修改项目。

## 本轮设计决策

把「需要先学会工具才能开始」变成「选一个镜头教程，跟着完成第一镜」。产品首页讲创作价值，教程详情讲具体怎么做，创作页完成一次真实提交，结果详情负责检查和保留，作品资产承接素材与成片。

保留 Vue 3、现有任务与项目模型，不新增影片工程、分镜任务系统、自动剪辑、订阅、供应商公开接口。三个镜头是教程内容的顺序，不代表服务端已有整片项目、批量调度或跨镜头人物一致性能力。

视觉沿用当前深炭灰与暖琥珀。公开页使用大画面、叙事标题、少量精选教程；工作台保留紧凑导航和输入/结果并排。丰富度来自镜头内容、构图与层级，不靠统计数字、装饰徽章或虚构案例。

## 五页的任务与入口

| 页面 | 用户要完成的事 | 主动作 | 去向 |
| --- | --- | --- | --- |
| 公开产品首页 | 理解能做什么，找到一个切入点 | 从「海岸来信」开始 | 镜头教程详情 |
| 镜头教程详情 | 理解素材要求、镜头顺序与提示词 | 跟做这一镜 | 带教程上下文的创作 |
| 跟做创作 | 确认模式、素材、提示词与生成参数 | 提交并按本次实时价格计费 | 新任务结果详情 |
| 结果详情 | 查看交付，下载、调整或保存 | 保存到选定作品 | 作品内页 |
| 作品资产 | 整理素材和挑选后的成片 | 进入作品 / 继续创作 | 目录、任务详情、下一镜 |

首页已实现为公开产品入口，未登录访问不读取私有概览。现有工作台概览保留。路由为：公开产品首页 `/`、制作教程 `/guides/coast-letter`、跟做创作 `/app/create?guide=coast-letter&shot=arrival`、结果 `/app/works/:id`、作品内页 `/app/assets?project=...&folder=视频/正片镜头`。老广场保留菜单名，入口内容替换为三个编辑教程，不继续呈现原来的 18 条通用视频演示。

## 教程内容

主教程「海岸来信」用文生视频练习三个镜头：建立场景 → 主体动作 → 情绪收束。每镜都有意图、提示词和跟做入口。副教程「产品光影」使用多图生成，「场景转场」使用首尾帧生成，两者都明确要求用户自行准备素材。

图片沿用仓库已有 Unsplash 海岸、手表与森林 URL，仅用于构图示意。不是平台生成案例，不声称是某段提示词的实际输出，不自动上传，不推断真实视频时长或分辨率。设计稿不使用 MDN 示例视频冒充成片。原型图片依赖外网；正式公开素材仍需审核来源、使用条件和稳定托管方案。

教程本身可以是经过审核的静态编辑内容；真实用户成片的公开案例展示需要单独的发布授权、素材来源和可撤回机制，不能从私有任务自动选取。

## 创作与计费边界

客户端继续只呈现模式、承运商、模型、时长、分辨率、画幅、自动音频与已实现的素材输入。供应商、API/workflow、上游编码、供应商成本、供应商额度与凭据始终不出现在客户端。用户自己的钱包余额正常显示。

教程入口只传递创作意图与安全参数，不传供应商信息。带入后重新读取目录与能力，校验仍可用；不保证静态教程建议是当前可售组合。预估使用现有 `/client/tasks/estimate`，无 quoteId、不扣费、不锁配置；提交带完整参数与新的幂等键，由后端重新路由、计价与事务扣款。

设计稿以「等待实时估价」展示费用，未编造 ¥0.20 等可售价格。提交按钮在原型中明确表示「查看提交后的结果页」，不会模拟生成成功。预估是辅助信息，预估失败本身不禁止提交；应明确提示提交时后端会重新计算并按本次价格扣费。素材不齐、已知余额不足或明确能力不可用时，沿用现有校验与提示，不把历史预估当成最终订单。

## 响应式与交互

- 桌面公开页以左右叙事、教程卡片和三镜头并列；工作台左输入右参考/结果。
- 手机先展示主任务，教程镜头纵向排列，创作输入在预览之前，结果参数卡在播放器之后。
- 设计稿底部导航仅用于审阅，不是产品最终底部导航。
- 案例/教程素材必须有清楚标签；图片加载失败不得转成伪视频成功状态。
- 结果页主动作是下载、保存与继续创作。原型的提示词回显和下一镜关联属于交互示意，当前服务端未提供持久化关联，实际页面不显示虚构提示词或进度。保存目标通过弹窗选择。失败/排队/交付中状态沿用服务端，不用本稿的「已完成 · 示意」写死。
- 作品内页保留文件管理，不增加剪辑时间线，也不以三张图暗示已经生成完整短片。

### 未通过的真实交付检查

已有任务 `tsk_20260922_…69ab`（编号已脱敏）返回「已完成 / ready」，但浏览器显示「视频预览暂不可用」。验证发现两项独立问题：

1. 结果存储地址为 `http://192.168.0.103:9000`。本机请求和从 107 请求 `/minio/health/live` 均被拒绝连接（没有收到 HTTP 响应），需恢复该 MinIO 服务或核实实际端点。
2. 已存下载地址签名时间为 `20260922T083650Z`，有效期 86400 秒，验收时已过期。代码确认 Worker 将 24 小时签名 URL 持久化，任务详情原样返回，资产下载也会跳转旧 URL。刷新页面不能续签；仅恢复存储服务仍不足以修复旧成片访问。

本轮前端发布未修改这两项后端/环境问题，不宣称预览、下载或完整收费交付通过。下一步优先恢复存储连通性，并在任务读取及资产下载时对可信自有对象续签；在对象仍存在且配置可访问原桶的前提下，可验证旧任务而无需再付费生成。还需覆盖地址来源校验、跨用户访问限制和签名失败状态，不能对任意外部地址续签。

## 下载续签修复与真实成片验收（2026-09-26）

用户恢复 MinIO 后，107 健康检查为 HTTP 200；旧成片仍返回 `403 AccessDenied / Request has expired`。本阶段已补齐 MinIO/COS 读取时续签，任务详情与资产下载先校验用户归属再签名，有效期 1 小时。旧 query 不复用，外部主机、其他桶与歧义路径不接受续签；失败返回 `503 DELIVERY_UNAVAILABLE`，不泄露旧地址或存储诊断，不回退裸 URL。列表缩略地址也续签，资产 DTO 使用受保护文件路由；Worker 日志不再输出完整签名。

本次后端修复没有新迁移。发布审查发现旧初始化会重放所有 SQL 和种子，可能重置售价、供给或历史任务字段。因此增加 `SUB2VIDEO_SKIP_BOOTSTRAP=true` 供已初始化、无 schema 变更的发布使用；107 已通过 `/etc/systemd/system/sub2video-backend.service.d/90-skip-bootstrap.conf` 启用。后续涉及 schema 的发布必须先执行经过审查的迁移，不能假设此选项会自动升级数据库。
