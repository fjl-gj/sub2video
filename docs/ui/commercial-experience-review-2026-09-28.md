# Sub2Video 页面体验与商业化评估

日期：2026-09-28。范围：当前工作区源码，以及 `http://192.168.0.107:12000` 的实际页面。

## 1. 结论与证据边界

Sub2Video 已有完整的视频创作工具骨架、统一视觉语言和真实业务页面。当前最需要补齐的是：真实效果证明、新手首次成片体验、可信的消费与恢复反馈、结果复用、售后与经营度量。继续更换整站主题，或仅重复供应商连通性测试，都不能解决这些问题。

目前适合创始人陪同的限量产品体验；不宜直接当作成熟自助商业产品规模获客。这个判断不以支付渠道是否接通为唯一标准。支付按用户要求暂缓，先通过现有余额、兑换功能组织受控试用。

- 当前分支：`codex/commercial-studio-redesign`；HEAD：`a479c330d90b468fa17f2b0b3ce79a3f415b0dae`。

## 2. 商业化成熟度

| 维度 | 已具备 | 仍缺少 | 当前判断 |
|---|---|---|---|
| 品牌与视觉 | 深色创作端、浅色管理端，同一中性/琥珀色体系；导航、表单、弹窗基线一致 | 部分页的内容密度、主次动作和空白区域用途不足 | 视觉基础成立，适合局部收敛 |
| 首页价值表达 | 三种创作方式、步骤、FAQ、教程入口 | 没有清晰突出“看你的短片→学会制作类似镜头”的独特路径 | 有产品说明，差异化不足 |
| 效果证明 | 参考影像和构图图示均诚实标注；已有私有历史结果页 | 缺公开真实输出、原始输入、尝试次数、总费用和改法 | 商业说服力明显不足 |
| 新手激活 | 教程可带入参数；登录可续接；创作和估价均有实现 | 首次进入仍需自行理解模式、模型、素材和六项参数；缺连续跟做路径 | 能使用，但上手依赖指导 |
| 消费信任 | 估价、订单、余额、任务和退款基础存在 | 刷新后的请求恢复风险；取消/退款承诺不一致；错误易随 Toast 消失 | 扩大私测前必须收敛 |
| 成片与复用 | 预览、下载、保存作品；本地已有原参数重做 | 保存入口不一致、刷新后缺准确归档位置、无作品时离开结果页 | 已有结果页，复用体验未闭合 |
| 售后服务 | 可创建工单、查看状态、后台标记处理中/解决 | 缺详情、回复、补充信息和结果反馈；后台只取前 50 条 | 不能依靠当前工单独立完成售后 |
| 经营与增长 | 真实任务/订单/账务基础，后台任务和供给总量 | 来源、教程转创作、首次成片、再次生成、成本与退款的经营口径 | 有运维后台，经营反馈不足 |

客户端深色、管理端浅色本身不构成风格冲突：二者服务不同工作场景，共用品牌、字体、控件和层级即可。107 当前两端已经基本满足这一点。后续遵循 `docs/ui/design-system.md`，不创建第二套设计系统。

## 3. 实际页面设计观察

| 页面 | 107 实际表现 | 设计调整方向 |
|---|---|---|
| 官网 | 首屏海岸影像、较强标题层级、清晰入口；明确标注实拍非生成 | 保留排版语言，把最重要的展示位逐步交给有授权的真实成片；标题具体说明用户能学会做什么 |
| 概览 | 三模式入口、最近成片、进行中任务、余额及存储 | 新用户突出“完成第一镜”的一个明确入口；老用户突出继续作品/最近结果，避免相同入口重复堆叠 |
| 创作桌面 | 左输入右预览已实现；约 1280×720 视口下，参数和费用需下滚；右侧未选素材时大面积空白，“预览与结果”标题重复 | 空预览承担素材清单/参考案例/跟做说明；按准备状态显示下一步；费用及主动作在可操作区域易于找到，而非单纯加更多卡片 |
| 创作手机 | 控件能收拢，底部导航存在；首屏大半被标题、作品选择、素材和提示词占据，费用与提交在更下方 | 减少重复余额/入口；输入优先，费用摘要与提交区考虑随步骤可达，避免与底部导航遮挡；需以实际手机流程验收 |
| 广场/教程 | 三套编辑教程，图片均为构图参考；教程有镜头拆解和“制作这个镜头” | 在现有路由上明确这是镜头教程与案例内容；先补真实可跟做案例，不伪装社区热度，不急着做社区功能 |
| 任务详情 | 大播放器、状态、参数、费用、下载、保存，结构已合理 | 增加稳定的原参数复用、明确归档位置和异常处置；保留媒体加载/错误反馈，不再扩展装饰 |
| 资产 | 当前把作品作为容器，里面收纳素材与生成镜头；默认作品显示“系统默认工程” | 文案统一解释“作品收纳素材与镜头”；用真实缩略图或内容摘要帮助识别作品，不靠假封面填空 |
| 钱包 | 107 大区块展示充值档位及原型微信入口；本地已禁用按钮但仍突出充值和赠送 | 支付暂缓期间以真实余额、兑换、流水、扣费说明为主；不要把未开放功能置于视觉中心 |
| 管理端 | 承运商包含下层模型列表；浅色表格、操作入口清楚；概览主要统计任务/供应商 | 保留结构；将待处理异常和用户问题放在运营重点，后续增加真实经营数据，不靠更多配置页体现成熟 |

## 4. 围绕用户获客方式的旅程

目标人群假设：看过创始人短片/短剧宣传内容、有故事想法但不熟悉模型和提示词的个人创作者，希望在可控费用下做出第一个可用短镜头。需通过首批访谈验证，不能当成已经确认的客户画像。

| 阶段/触点 | 用户动作及疑问 | 预期情绪（待验证） | 当前断点 | 机会 |
|---|---|---|---|---|
| 短视频宣传→案例页 | “这真是这里做的吗？我也能做吗？” | 好奇，但怀疑 | 官网展示参考影像，尚无完整真实案例证据 | 将宣传片与具体教程对应，标清生成、剪辑和配音各自来源 |
| 案例→教程 | 看输入图、提示词、输出和费用 | 想尝试，但怕失败浪费 | 只有文字练习，无法对照真实效果 | 给成功参数、失败例子、调整原因、尝试总费用 |
| 教程→登录→创作 | “我该上传什么，选哪个参数？” | 有目标，但操作负担较大 | 教程带入已实现，创作仍像参数表 | 保留教程目标、素材清单和当前步骤；能力受实时目录约束 |
| 估价→提交 | “大概要花多少？重复点会不会扣两次？” | 谨慎 | 错误过短、网络丢响应后的刷新恢复有风险 | 持续显示估价/失败原因，保留同一请求，明确费用结算规则 |
| 等待→结果 | “可以离开吗？失败了钱在哪？” | 等待焦虑 | 取消退款文案与实际边界不一致 | 按真实状态说明可做什么，显示退款金额/时间，提供关联工单 |
| 结果→保存→再次制作 | “存在哪里？怎样调整或做下一镜？” | 满意或想修改 | 保存目标/返回路径不稳定；教程上下文未贯通 | 弹窗内选或新建作品，刷新可直达，保留原参数和下一镜入口 |
| 复用→推荐 | 再做同类镜头、展示自己的成果 | 有信心，愿意分享 | 尚缺真实复用测量及案例整理机制 | 先让用户自行下载分享；经授权整理案例，不急做公开社区 |

首次价值时刻应定义为：用户看到基于自己输入产生的可用结果，并能下载或保存找到。不是仅注册成功、估价成功或任务 HTTP 200。

关键决策点：是否相信案例、是否愿意消耗第一笔余额、发生异常后是否相信平台、第二次是否愿意继续使用。当前没有数据证明在哪一环流失最多，需要后续量化。

## 6. 商业内容与运营的最小建设

### 6.1 先完成一个真实案例

优先使用你已有、可授权公开的一个短片或短剧宣传片。不必为连通性重新批量生成，更不能将实拍素材替换标签后冒充生成样片。

案例需要：最终成片、逐镜头输入、实际输出、提示词、公开模型与参数、生成日期、实际费用、总尝试次数、等待时间、失败/重做原因、外部剪辑步骤、素材许可。历史实际费用与当前实时估价分开，不能拿一次成功镜头的费用冒充整片总成本。

页面顺序：成片与用途 → 如何做出来 → 输入/输出对照 → 镜头拆解 → 制作这个镜头。复用现有教程和带参创作能力，不建设完整影片工程。

“便宜”必须通过可复现的实际成本证明。当前页面中的测试价格，不等于已经验证的正式商业定价或利润。

### 6.2 让第一次和第二次创作连续

保留现有左输入右预览。输入前帮助准备素材，输入中说明能力与费用，结果后帮助保存和调整。新用户侧重一个跟做入口，老用户侧重最近作品与继续创作。模型选择保留；默认推荐不等于静默跨模型切换。

“做下一镜”可先仅为教程导航和参数带入；未经实现和验证，不承诺人物一致性、自动剪辑或完整短剧生成。

### 6.3 最小经营反馈

先利用已有任务、订单、流水统计消费、交付、退款和再创作；仅补当前没有的必要来源及页面行为。不要为做看板先引入新服务。

- 获客：宣传内容来源、案例/教程访问、教程开始创作。
- 激活：估价成功、首次提交、首次成功交付、首次下载/保存；区分用户和任务口径。
- 复用：首次成片后 7 日内再次提交的用户比例，明确分母与观察窗口。
- 服务：失败原因、退款完成时间、待核对任务、工单首次回应和解决情况。
- 经营：平台消费与退款、供应商成本、存储/流量成本、失败尝试成本；只在数据齐备时称为毛利。

当前源码审查未发现完整的来源归因及这条激活漏斗实现。107 管理首页主要是任务与供给总量，不能据此判断真实转化率、留存率或商业成功。

## 7. 下一轮实施顺序与验收

| 顺序 | 工作包 | 退出条件 |
|---|---|---|
| 1 | 可信创作：请求恢复、草稿素材状态、持久错误、取消/退款说明、钱包未开放入口收敛 | 刷新不产生第二笔购买；素材状态真实；所有异常都有正确下一步；不再展示原型充值成功路径 |
| 2 | 一个真实案例与跟做入口：首页、教程、创作衔接 | 访客能看真实输出和输入，理解费用与重做成本，带入参数后保留来源；已有草稿受保护 |
| 3 | 交付与复用：保存到作品统一、弹窗新建、准确返回、继续教程/原参数 | 保存后刷新仍可找到同一成片；列表/详情行为一致；新用户无作品也能直接保存 |
| 4 | 最小私测运营：工单回复与分页、异常核对入口、必要行为统计 | 用户与管理员完整完成一轮售后；可区分案例访问、首次生成和重复使用；指标可核对真实订单 |
| 5 | 体验验收与发布对齐 | 桌面/移动端完整旅程通过；本地与 UAT 版本、能力和文案明确对应；再邀请小批真实新用户验证 |

本次不实施代码，上述是推荐顺序，不代表已经完成。新数据合同是否需要迁移，须在对应工作包中检查现有模型后决定；不能为了规划先新增表或服务。

有价值的浏览器验证是：一个第一次使用的人能否理解、完成、恢复和复用。至少覆盖空账户、已有作品、素材刷新、提交丢响应、余额不足、无供给、待核对、退款、媒体异常和保存后刷新。视觉回归用于检查层级和布局；真实 API/数据库用于检查持久化和消费；真实供应商用于验证新执行链路。三者证据不能互相替代。

不重复付费生成来证明首页好看。只有在执行、素材访问或交付路径发生实质变化，或要制作经授权的公开案例时，才安排有预算的真实生成。
