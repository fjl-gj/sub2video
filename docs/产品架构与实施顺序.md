# Sub2Video 产品架构与实施顺序

完整产品菜单与职责以 [产品方案总览](./产品方案总览.md) 为准；创作、报价和供给边界以 [创作模式与供应商路由设计](./创作模式与供应商路由设计.md) 为准。

## 已实现基础

- Vue 3 客户端和管理端，使用独立路由与共享设计系统。
- Go + Gin API、JWT 身份验证、PostgreSQL 迁移、钱包流水、作品工程和上传素材。
- MinIO/COS 对象存储抽象、AutoDL H3 Adapter、异步任务 Worker。
- 三个固定创作模式、模型可见/供应商隐藏、报价快照和任务预扣。

## 当前架构

```text
Vue Client/Admin
       │ HTTPS /api/v1
       ▼
Gin API ─ PostgreSQL（用户、钱包、目录、报价、任务、供给）
       ├─ Redis（连接与异步基础设施）
       ├─ Object Storage（素材与结果）
       └─ Worker / Adapter（锁定供给的上游调用）
```

## 后续实施顺序

1. 为承运商、模型、供给、成本和售价管理操作补齐可查询的审计日志。
2. 接入已确认的官方 MiniMax、火山引擎供给；每条供给先确认能力、上游参数映射和成本，再上架。
3. 为报价、并发提交、退款和 Worker 锁定路由添加 PostgreSQL 集成测试。
4. 将 Worker 从轮询模式拆为可观测的队列消费者，并补齐供应商健康检查。
5. 完善支付回调、任务下载签名和生产环境部署监控。
6. 参考音频、实际输出时长结算和其他生成能力均作为独立输入合同和结算项目，不复用“自动生成音频”。
